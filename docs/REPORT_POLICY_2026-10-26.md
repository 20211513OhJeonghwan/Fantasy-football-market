## 계수

사용자가 선택한 보고서 예시 계수는 κ=4, β=0.3, 분모 하한 s=1, 경기당 상승·하락 각각 2%다. 보고서에 없는 나머지 기본값은 설정으로 명시했다.

- 표본 보정 λ=5, 상대 편차 제한 D=1.
- 초기·전역 가격 범위 10,000~1,000,000P: 기존 전역 가격 범위를 유지.
- 새 경기 점수 보정 범위 L/U: 고정된 이전 시즌 포지션 점수 분포의 5/95백분위. 원점수와 기여도는 수정하지 않는다.
- 백분위 `(작은 값 수 + 동점 수/2) / 모집단 수`. 표본이 하나이거나 모두 동점이면 50%다.
- 새 시즌의 누적 분자·출전 수는 새로 시작하고, 발행 가격·지갑·보유·거래는 이어간다. 최초 기준 모집단은 버전의 고정 기준을 유지한다.
- 정수 반올림 뒤 ceil(직전가×0.98)~floor(직전가×1.02)로 다시 제한한다.

`report-policy.ts`, DB `kickx_policy.report_parameters`가 이 기본값을 명시한다. 다른 계수는 새 기준 세대로 검증하여 전환한다.

## 이전 시즌 준비와 전환

검토 시 DB에는 2026시즌만 있었다. 사용자가 이전 시즌 확보를 선택했으므로 현재 시즌 기록이나 임의의 50점으로 대체하지 않는다.

1. 기존 유지관리 Actions가 실제 이전 시즌과 5대 리그의 종료 경기 전체를 페이지별로 찾는다.
2. 경기당 detail/player-stats/lineups/incidents를 읽고 새 배점으로 계산한다. 이전 시즌 선수 프로필을 따로 호출하거나 현재 선수의 소속을 과거 팀으로 변경하지 않는다.
3. 원천과 계산 결과는 기존 비공개 Storage 버킷에 gzip·SHA-256으로 보관하고 다운로드 검증한다. DB에는 원천 JSON을 경기마다 복제하지 않는다.
4. 수집 진행 상태도 압축 체크포인트에 보관한다. DB에는 작은 포인터·진행 수치만 저장한다. 검증된 새 포인터를 CAS 저장한 뒤 대체 가능한 이전 진행 파일만 제거한다. 원천 증거는 유지한다.
5. 전 경기 조회가 끝나고 GK/DF/MF/FW의 사용 가능한 기준이 만들어지면 고정 모집단을 저장한다. 개별 선수 기록이 없으면 검증된 포지션 평균을 사용하고 `position-prior`로 표시한다.
6. 운영 API가 `report-v3` 지원 헤더를 반환하는 것도 확인한 뒤 새 정책을 활성화한다. 준비 실패·API 한도·배포 대기 중에는 기존 활성 정책과 기존 가격을 유지한다.
7. 기존 자동 계산 큐가 새 점수와 가격을 발행한다. 선수별 재산정 중에는 이전 가격을 보존하고 새 거래를 잠시 보류한다. 완료된 거래·지갑 잔액·취득 원가는 소급 수정하지 않는다.

수집은 기존 공유 7,000회/일 예약 한도에 포함하며, 과거 자료 작업은 1,500회 이상의 라이브 여유를 남긴다. 새 Cron·공개 관리 API·키 전달 경로는 추가하지 않았다. 큰 기준 JSON은 익명/회원에게 직접 노출하지 않고, 정책 활성화 뒤 정기 작업이 이를 반복 다운로드하지 않는다.

## 출전시간 보완

정규 경기의 90분 초과 출전을 일률적으로 차단하던 문제를 새 계산기에서 수정했다. 같은 경기의 두 개 이상 기록으로 추가시간을 교차 확인하며, 단일 비정상 카운터가 경기 길이를 결정하지 못하게 한다. 실제 출전·교체·득점 시각 검증을 유지한다.

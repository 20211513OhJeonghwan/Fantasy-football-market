# DB 저장량과 egress 개선 · 2026-10-20

## 적용 범위

완료한 수집 작업의 중간 payload 정리, 기존 경기 점수 재사용, 공개 조회 캐시와 과거 계산 상세의 압축 보관을 구현했다. 선수·경기 원본의 90일 보관 제한은 이번 범위에 포함하지 않았다.

## 계산과 전송량

- `kickx_calculation_input`은 경기 통계·경기·이벤트 원본 수정 시각과 점수 규칙을 비교해 바뀐 경기의 계산 입력만 반환한다. 최초 사용 시 해당 선수 기록을 한 번 계산하고 이후에는 기존 점수를 재사용한다. 전체 선수에 대한 강제 재계산은 하지 않는다.
- `kickx_publish_calculation_delta`는 원본 변경 토큰을 다시 확인하고 저장된 점수와 새 점수를 DB 안에서 합친다. 기존 기본 가치·최근 5출전 가격 수식으로 검증하며, 과거 정정도 전체 계산과 같은 가격을 만든다. 필요한 가격 경로의 재검증은 PostgreSQL 내부에서 수행하므로 과거 경기 원문과 점수 상세를 워커에 다시 전송하지 않는다.
- 점수가 같아도 출전 시간·경기 날짜·시즌 변경은 가격 검증을 다시 수행한다. 입력이 같으면 계산 이력과 가격 변동을 중복 발행하지 않는다. 바뀌지 않은 경기 점수·기록·가격 단계도 불필요하게 지웠다 다시 쓰지 않는다.
- AI 리포트의 점수·가격 연결은 경기별 `input_hash`로 유지한다. 정정이 보류된 가격에 새 점수를 섞어 리포트를 만들지 않는다.
- 공개 홈 데이터, 선수·경기 목록과 선수 상세는 익명 클라이언트로 읽어 Next.js 서버 캐시에 15초 재검증 간격으로 공유한다. 재검증 시 이전 값이 잠시 보일 수 있다. 로그인, 잔액, 보유/관심 목록, 사용자별 공감 상태, 거래 견적·체결 및 AI 리포트 권한 검사는 캐시 밖에서 수행한다. HTTP 응답의 private/no-store 정책은 유지한다.
- 공개 정책 조회는 필요한 6개 필드만 요청한다.

## 데이터 보관

- 완료된 `automation_daily_tasks`, `club_collection_tasks`의 payload를 비운다. 성공 여부·작업 종류·식별자·라벨은 남기며 진행 중인 작업의 재시작 지점은 유지한다. 완료 시점의 트리거로 재누적을 방지한다. 재수집은 seeder가 새 payload를 공급한다.
- 선수별·규칙별 최신 전체 계산은 DB에 남긴다. 이전 계산 상세는 비공개 Storage 버킷 `kickx-calculation-archives`에 최대 250행씩 gzip으로 저장한다.
- 파일명은 압축 바이트의 SHA-256이다. 업로드 뒤 파일을 실제로 다시 다운로드해 일치하는지 확인한 다음, DB에서도 ID·원래 상세의 해시와 최신 여부를 다시 확인하고 `results=[]`, `pricing=NULL`로 정리한다. 변경 전후 가격·규칙·입력 해시·시각·actor·archive_path는 남긴다.
- 업로드/다운로드/검증 실패 시 상세를 정리하지 않는다. 업로드 완료 후 응답을 놓쳐도 같은 파일을 검증해 재시도할 수 있다. 백업의 rows에는 원래 revision의 모든 필드와 검증 해시가 들어 있다.
- 내부 API `/api/internal/storage-maintenance`는 DB의 service-role RPC 실행 권한으로 인증하며 결과 카운터만 반환한다. 키·원문·백업 내용은 응답하거나 기록하지 않는다.
- pg_cron은 매시 11·26·41·56분에 정리 필요 여부를 확인한다. 대상이 없으면 HTTP 요청도 보내지 않는다. HTTP 대상은 기존 본인 사이트의 고정 주소이며 자격 증명은 기존 Vault의 워커 키를 사용한다.
- 자체 분 단위 워커·압축 보관 작업의 실행 로그는 7일, 반복 보류·랭킹 갱신의 보조 감사 기록은 30일 유지한다. 거래·원장·자산·가격 이력과 정책·관리자 조치 기록은 삭제하지 않는다.
- Storage의 압축 파일은 별도 저장 용량을 사용한다. 장기 보관 파일까지 무제한 무료라는 의미는 아니다.

## 적용 전 실측

2026-10-20 20:43:57 KST: 전체 DB 208,370,485바이트, 완료 작업 payload 8,737,371바이트, revision 10,410행, 점수 18,195행, 거래 2건. 기존 가격 checksum `939b645520c74612c2418fa75a6d100b`, 잔액 checksum `a21f82c9d425f29b0bb4c84dcae08a8b`.

가격·잔액의 체크섬과 원본 수량을 운영 적용 후 비교한다. 누적 egress는 이미 전송한 양이어서 내려가지 않는다. 개선 후 소비 속도는 완결된 일자와 대조해야 하며, 응답 샘플 감소율을 전체 egress 절감률로 해석하지 않는다.

이번 작업에는 테이블을 잠그는 VACUUM FULL이 포함되지 않는다. 삭제·축소한 행의 공간은 일반 VACUUM 이후 재사용될 수 있으며 표시되는 물리 크기의 감소량과 JSON 정리량은 다르다.

## 검증

로컬에서 204개 단위 검사, 전체 마이그레이션과 DB 회귀 검사, lint 및 프로덕션 빌드를 통과했다. 추가 검사에는 캐시 적중 시 과거 기록 0건 전송, 과거 점수·출전 시간·경기 날짜 정정의 전체 계산 대비 동일성, stale/외부 fixture 거부, 불변 점수 쓰기 방지, 리포트 해시 정합성, 최신 revision 보존, 검증 실패 시 무삭제, 익명·회원 역할의 내부 RPC/정리 API 차단, 공개 캐시와 회원 공감 상태 분리가 포함된다.

운영 적용·배포 결과는 후속 실측에서 확인한다.

## Claude 디자인 인계

화면 구조 변경은 없다. 공개 가격은 15초 재검증 캐시를 거치지만 견적과 거래 가능 여부는 서버가 현재 DB로 재검사한다. 거래·로그인·AI 리포트 API를 공개 캐시에 합치지 않는다. 완료 작업의 payload가 비어 있는 것은 정상이며 성공 여부·마지막 확인 시각으로 상태를 표시한다. AI 리포트 버튼과 로그인 제한은 기존 동작을 유지한다.

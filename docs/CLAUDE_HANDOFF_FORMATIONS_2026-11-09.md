# 포메이션 변경·동결 벤치 디자인 인계

이 문서가 스쿼드에 관한 이전 인계장보다 우선한다. 기존 구단별 유니폼·테마, 선수명 표시와 매각 패널 개선을 유지하면서 아래 기능의 시각적 완성도를 높인다.

## 1. 확정된 동작

사용자가 최종 선택한 방식은 **새 포메이션의 포지션 정원을 넘는 선수만 직접 골라 동결 벤치로 보내는 것**이다. 포메이션 변경 때 전원을 벤치로 보내지 않는다.

1. 스쿼드의 `포메이션 변경`을 누른다.
2. 새 포메이션을 선택하면 GK·DF·MF·FW별 현재 인원과 변경 후 정원을 표시한다.
3. 초과 포지션마다 필요한 수만큼 벤치 이동 선수를 선택한다. 예를 들어 4-3-3의 주전 11명에서 3-5-2로 변경하면 DF 1명과 FW 1명을 선택한다.
4. 확정하면 선택한 보유분만 적용 시점 가격으로 동결하고 나머지 주전은 유지한다. 이 예에서는 MF 자리가 2개 비어 매입할 수 있다.
5. 동결 선수는 **주전으로 복귀할 수 없다.** 기존 이적·포지션 변경 벤치와 동일하게 이동 시각부터 14일 동안 직접 매각할 수 있고, 이후 기존 자동 작업에서 매각한다. 수동·자동 매각 수수료는 모두 2%다.

벤치는 배치 가능한 후보 선수 명단이 아니라 매각 유예 중인 보유분이다. 공개 선수 가격 자체를 동결하는 것이 아니라 해당 회원의 보유 평가액과 매각 가격을 동결한다. 기존 벤치의 가격·시작 시각·기한을 다시 설정하지 않는다.

경기 거래 제한 중인 주전은 자발적인 벤치 이동 대상으로 선택할 수 없다. 서버에서도 검사한다. 선택 대상이 없는 변경은 벤치 생성 없이 진행한다. 취소하면 아무것도 저장하지 않는다.

## 2. 지원 포메이션과 포지션 정원

제공된 표에서 4-6-0, 3-6-1, 3-3-3-1을 제외한 19개를 지원한다. 첫 숫자는 DF, 마지막 숫자는 FW, 사이 숫자들은 모두 MF다. GK는 항상 1명이다. 세부 AM·DM·윙 포지션을 새로 만들지는 않았다.

| 포메이션 | DF | MF | FW |
| --- | ---: | ---: | ---: |
| 4-3-3 / 4-1-2-3 | 4 | 3 | 3 |
| 4-4-2 / 4-3-1-2 / 4-2-2-2 | 4 | 4 | 2 |
| 4-2-3-1 / 4-3-2-1 / 4-1-4-1 / 4-5-1 / 4-4-1-1 | 4 | 5 | 1 |
| 4-2-4 | 4 | 2 | 4 |
| 3-5-2 / 3-4-1-2 | 3 | 5 | 2 |
| 3-4-3 | 3 | 4 | 3 |
| 3-4-2-1 / 3-2-4-1 | 3 | 6 | 1 |
| 5-3-2 | 5 | 3 | 2 |
| 5-4-1 | 5 | 4 | 1 |
| 5-2-3 | 5 | 2 | 3 |

같은 정원의 포메이션도 경기장의 줄 구분은 다르다. 예를 들어 4-3-3과 4-1-2-3은 정원은 같지만 MF를 표시하는 줄 수가 다르다. 슬롯은 GK부터 DF, MF, FW 순서로 저장하고 화면에는 역순으로 배치한다. 홈의 작은 스쿼드도 실제 선택 포메이션을 표시한다.

## 3. 주전 배치 기능

`선수 배치`를 누르고 주전 선수를 선택한 다음 같은 포지션의 자리를 선택하면 이동하거나 서로 교환한다. 저장은 즉시 이루어지고 `배치 완료`로 모드를 종료한다.

- 같은 포지션 안에서만 이동 가능하다. 여러 MF 줄 사이 이동도 MF끼리라면 가능하다.
- 보유한 주전 전체를 배치에 포함해야 한다. 주전을 임의로 숨기거나 동결 벤치를 끌어올 수 없다.
- 매입하면 빈자리에 자동 반영되고 매각하면 해당 자리가 비워진다. 기존 자동 반영 흐름을 유지한다.
- 포메이션과 포지션별 정원은 스쿼드의 작은 선수 시장 및 전체 선수 시장 매입 모달에도 적용된다.
- 변경 중 재클릭을 막고, 다른 화면에서 선수나 배치가 변경되면 최신 revision을 요구한다.

| 화면 | 현재 구현 |

남은 시간은 `자동 매각까지 13일 23시간 59분`, 1분 미만, 기한 경과 시 `자동 매각 처리 중` 상태를 구분한다. 화면 안에서 30초마다 계산하며 서버 요청을 보내지 않는다. 실제 자동 매각은 서버 작업 실행 시 처리하므로 표시 시간이 0이 되었다고 화면에서 잔액을 임의로 늘리면 안 된다.

## 5. Claude에게 요청하는 디자인 보완

- 변경 전후 정원과 선택해야 할 인원을 더 빠르게 이해할 수 있게 모달의 정보 위계를 정돈한다. 체크 개수와 확정 버튼 상태를 유지한다.
- `선수 배치` 모드에서 선택한 선수와 이동 가능한 같은 포지션 자리를 명확하게 구분한다. 모바일에서도 첫 선택·두 번째 선택 흐름이 보이게 한다.
- DF 5명, MF 6명, 5줄 포메이션을 320px 화면과 홈의 작은 경기장에서 확인한다. 이름·가치가 옆 선수와 겹치지 않도록 한다. 전체 이름은 title과 접근성 이름에도 남겨둔다.
- 주전 경기장과 동결 벤치의 성격을 시각적으로 구분한다. 벤치에 드래그·배치·복귀 동작을 추가하지 않는다.
- 카운트다운, 동결 가격, 매각 버튼은 작은 화면에서도 동시에 식별되게 한다. 긴 선수명·사유·기한의 줄바꿈을 확인한다.
- 마감 후 처리 중 상태, 경기 거래 제한, 데이터 갱신으로 생긴 revision 오류, 저장 실패의 표시를 다듬는다. 취소·Escape로 저장 중인 동작을 중복 실행하지 않도록 유지한다.
- 기존 구단 테마와 유니폼, 팀원 main에서 반영된 긴 선수명 축소·전체 이름 툴팁·매각 후 패널 상태 유지를 보존한다.

포메이션 변경은 `POST /api/kickx/squad/formation`에 `{formationId, benchPlayerIds, revision}`을 보낸다. 가격·벤치 시각·회원 ID는 클라이언트가 정하지 않는다. SQL RPC는 `kickx_change_formation(text,text[],integer)`다.

주전 배치는 기존 `PUT /api/kickx/squad`에 `{formationId, slots, revision}`을 보낸다. `slots`는 null을 포함한 정확히 11개다. 이 API로 포메이션을 바꾸거나 벤치로 선수를 보내면 거부된다. 성공 후 공통 회원 데이터를 다시 조회한다.

## 7. 데이터·사용량

새 테이블, 가격 스냅샷, API 수집, 주기적 HTTP 요청, Cron은 추가하지 않았다. 기존 holdings의 동결 필드와 14일 자동 매각 작업을 재사용한다. 포메이션 변경을 확정할 때 스쿼드 1행과 선택한 보유분만 갱신한다. 배치 변경은 스쿼드 1행만 갱신한다. 카운트다운은 DB 저장값을 매번 변경하지 않는다.

마이그레이션은 운영 DB에 적용했다. 함수와 기존 제약을 변경하며 기존 선수를 자동 벤치 이동시키거나 가격·지갑·거래를 재산정하지 않는다. 적용 전후 거래·지갑·보유분 체크섬이 동일하고 기존 54개 스쿼드도 유지됨을 확인했다. DB 크기 증가는 적용 직후 8KB였다. 파일명은 운영에 기록된 마이그레이션 버전과 맞췄으므로 재실행하지 않는다.

## 8. 검증 지점

- `npm test`: 포메이션 목록·줄·정원, 초과 인원, 중복 보유, 동결 선수 제외, 기한 경계, 신규 API 입력·로그인·origin.
- `npm run test:db`: 전체 SQL 회귀 검사. 초과 인원 정확성, 경기 제한 우회 방지, stale revision, 변경 전 견적의 새 정원 검사, 주전 교환, 벤치 복귀 금지, 14일 자동 매각과 2% 수수료·중복 정산 방지.
- `tests/formations-browser.mjs`: 320/390/1440px 모달 취소·선택·변경·주전 교환·매입 정원, 기존 벤치 기한 보존, 19종 경기장 줄·11자리·가로 넘침.
- 기존 벤치·거래·커뮤니티·알림·프로필 브라우저 검사는 계속 유지한다. `.github/workflows/check.yml`에 포메이션 검사를 연결했다.

브라우저 검사는 가짜 회원·API 응답으로 진행하므로 운영 회원의 실제 선수나 자산을 이동시키지 않는다.

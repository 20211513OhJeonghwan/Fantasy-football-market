# Claude 디자인 인계: 선수 상세와 경기별 산정 내역

2026-11-03 사용자 요청 기준. 아래 삭제·문구·데이터 수정은 적용한 상태다. 전체 사이트 브랜딩을 바꾸지 말고 선수 상세의 Performance 내역을 중심으로 이어서 디자인한다.

## 적용한 화면 변경

- 선수 배너 아래의 Performance·득점/도움·출전 시간·거래량 통계 4칸과 숫자 설명 띠를 삭제했다.
- `내 보유 현황`과 `선수 가치 산정 근거` 영역을 삭제했다. 선수 배너의 매입·매각·관심 기능은 유지한다.
- `가치 흐름`을 `변동 기록 / VALUE HISTORY`로 바꿨다.
- 가치 차트는 파란 선과 옅은 파란 영역, 하락 기간은 빨간 선과 옅은 빨간 영역을 쓴다. 이 색상은 선수 상세에만 적용한다. 최근 Performance 막대도 파란 계열로 바꿨다.
- 산정 정책의 내부 버전 문자열은 선수 상세 화면에서 표시하지 않는다. 서버의 정책 식별자·캐시·검증은 유지한다.
- Performance 각 경기의 헤더에 리그 배지와 리그 이름을 추가했다.

## 이어서 디자인할 부분

사용자가 특히 부실하다고 지적한 부분은 하단 `Performance 산정 내역`이다. 현재는 기본 아코디언 구조를 유지하며 리그 정보와 문구를 보완한 상태다.

1. 리그·상대 구단·날짜·경기 결과·출전 분·총점을 한눈에 읽을 수 있게 묶는다. 경기별 대회는 `player.records[].leagueId`에서 읽는다. 현재 소속 리그로 과거 경기를 추정하지 않는다.
2. 펼친 영역에서는 큰 가점·감점과 총점의 관계를 먼저 보여준다. `row.breakdown`에 저장된 `metric`, `value`, `points`가 근거다. 프론트에서 점수를 다시 계산하거나 누락 기록을 0으로 채우지 않는다.
3. 산정 완료, 필수 기록 확인 필요, 미출전을 구분한다. 실제 보류가 남은 경기를 디자인만으로 완료로 바꾸지 않는다.
4. 데스크톱의 넓은 가로 공간과 모바일의 짧은 행을 각각 정리한다. 키보드로 아코디언을 열고 닫을 수 있어야 한다.
5. 최근 경기 표·AI 리포트·산정 내역의 시각적 연결을 검토하되, 이번에 삭제한 통계·보유·가치 근거 패널은 다시 추가하지 않는다.

## 잠정 산정의 의미

기존 계산기는 필수 기록이 검증돼 점수와 가격을 발행한 결과도, 공급자가 제공하지 않은 선택 통계를 제외했다는 이유로 모두 `provisional`로 저장했다. 따라서 이 상태는 가격 미확정과 같지 않다.

화면에서는 이 결과를 `산정 완료`로 표시하고, 펼친 근거에서 확인된 기록만 반영했다는 내용을 설명한다. 내부 품질 상태와 누락 항목 경고는 보존한다. `blocked`는 실제 필수 원천 문제이며 여전히 보류한다. 요약에서는 두 완료 상태를 합쳐 중복된 완료 배지를 만들지 않는다.

## 실제 계산 복구

추가시간이 포함된 출전 분을 정규 경기 시각의 교체·퇴장 기록과 직접 비교해 정상 기록을 보류하던 검증을 수정했다. 실제 추가시간 공지와 45+/90+ 사건 시각 범위 안에서만 인정한다. 임의의 출전 분이나 득점 시각을 만들지 않는다.

경기 종료 후에도 남아 있는, 적용되지 않았다고 명시된 VAR 검토 때문에 경기 전체를 보류하던 문제도 수정했다. 미확인·적용된 검토와 카드/득점 불일치 검사는 유지한다.

운영 DB의 원천을 경기별 한 번씩 읽어 계산했고, 원천 시각과 기존 보류 결과가 여전히 같은 경우에만 기존 발행 함수를 통해 반영했다. 신규 원천이 도착한 선수는 변경된 기록도 함께 확인했다. 285명을 처리해 279명의 가격 보류를 해소했고, 6명은 다른 필수 기록 문제로 보류를 유지했다. 현재 시장 범위 밖 16명은 가격을 재산정하지 않았다.

검증 시점의 현재 시즌 종료 정규 리그는 **완료 412/452경기(약 91.2%)**, 일부 38경기, 보류 2경기다. **11월 종료 35경기는 전부 완료**다. 남은 보류를 가짜 완료로 표시하지 않는다. 보류 선수 대기열은 416명에서 137명으로 줄었다. 이후 실제 경기 수집에 따라 숫자는 달라질 수 있다.

작업 중 실제 거래도 발생했으므로 전후 금융 테이블 전체 해시가 같은 상태라고 설명하지 않는다. 재산정 코드는 거래 원장·지갑 잔액·보유 취득 원가를 수정하지 않았으며, 실제 거래의 원장 연결과 보유 취득 거래 연결의 일관성을 확인했다.

## AI 리포트 복구와 비용

리포트의 DB 조회 함수에 이전 정책의 `평가 출전 5개 이하` 조건이 남아 있었다. 시즌 누적 평가가 6경기 이상이면 점수·가격이 모두 있어도 리포트가 차단됐다. 현재 정책에서는 시즌 누적을 허용하도록 수정했다.

실제 출전과 점수·가격 결과가 함께 있는 **4,579건 전부**에서 리포트 근거를 조회할 수 있음을 확인했다. 최신 점수와 가격의 입력 해시·정책 일치, 해당 경기가 평가 기록에 포함되는지, 로그인 권한 검증을 유지한다.

기존 최초 요청 1회 생성·공유 캐시·중복 생성 잠금·90일/3,000건 보관 한도·일/분/회원별 생성 한도는 변경하지 않았다. 이번 데이터 복구를 위해 AI 리포트를 일괄 생성하지 않았다. BSD 추가 호출도 없었다.

- `scripts/prepare-score-repairs.mjs`: 원천의 변경 여부를 검증하는 제한된 재산정 SQL 준비 도구. 자동으로 DB에 실행하거나 데이터를 지우지 않는다.

# KICK-X 페이지별 구현 현황

기준: 2026-10-01. 기존 배포 코드, 전달된 진행 요약, 직접 확인한 Yellow Playbook 레퍼런스 이미지를 기준으로 보완했습니다. 첨부 수정3(1).docx는 파일을 불러올 수 없어 문서 고유의 요구사항과 최종 대조가 필요합니다.

## 이번 변경

- 기존 20개 화면 유지 + 경기 일정 1개 추가: **총 23개 화면** (구단/선수 커뮤니티 분리).
- Google OAuth 시작/콜백/로그아웃, 서버 세션 검증, 프로필 저장, 관심 선수 저장 구현.
- 공개 리그·구단·선수·가격/경기 기록·일정 조회 어댑터와 11개 테이블 마이그레이션/RLS 추가.
- 운영 DB에는 자동 적용하지 않음. SQL + OAuth + 환경변수 설정 후 활성화.
- 홈의 정보 구분·표·점진적 더 보기·지표 설명·시작 가이드, 모든 페이지의 공통 디자인 세부 개선.
- 테스트용 데이터는 tests에만 존재. 앱과 SQL에는 가짜 계정·선수·가격·잔액·기록이 없음.

## 디자인 디테일

- 화면을 감싸는 종이색 여백, 정돈된 상단 메뉴, 현재 위치 표시와 경기 일정 접근.
- 제목/섹션 번호/표 헤더/단위의 크기·굵기 구분.
- 노란 자산 패널, 회색 피치, 얇은 규칙선과 절제된 그림자.
- 카드/행 호버, 키보드 포커스, 최소 클릭 영역, 모바일 검색 줄바꿈/표 스크롤.
- 빈 데이터·로딩·오류·저장 중·성공 상태를 구분. 오류 입력은 유지.
- 장식 이미지는 기존 레퍼런스 자산을 사용. 실제 선수 사진으로 취급하지 않음.
- 모션 감소 설정에서는 애니메이션/호버 이동 해제.

## 데이터 경계

GET /api/kickx → readPlatform → 서버 Supabase 어댑터 → 검증된 세션 + 공개 카탈로그 + 본인 관심 선수.
GET /api/kickx/admin → 관리자 역할 검사. 운영 어댑터는 아직 미연결.
POST /api/kickx/profile, PUT /api/kickx/watchlist → 동일 출처 검사 + 서버 세션 + 입력 검증 + RLS.

유효한 설정이 없으면 기존 미연결 응답을 유지합니다. DB 오류는 오류로 반환하며 성공한 빈 데이터로 숨기지 않습니다. 원장 미구현은 financialReady=false로 구분해 거래 합계/보유 수량에 가짜 0을 만들지 않습니다.

## 검증 범위

GitHub Actions에 린트, Node 단위 테스트, Next 프로덕션 빌드/타입 검사, 임시 PostgreSQL 마이그레이션/RLS 검사, 21개 경로의 데스크톱·모바일 브라우저 검사를 구성했습니다. 검사 결과는 해당 커밋의 Actions 실행을 기준으로 확인하세요. 테스트 주입 응답은 실제 Supabase OAuth 통합 시험을 의미하지 않습니다.

# 신규 선수 한글명 누락 보완

기존 3,122명 정적 명단 밖의 신규 선수도 한글 표시명을 채운다. BSD 선수 전체를 조회하며 현재 시장 표시 여부, 소속 구단 또는 생년월일이 없다는 이유로 음역 초안을 제외하지 않는다. 기존 검수·수동 이름과 원어 이름·선수 ID·가격·지갑·거래는 보존한다.

`scripts/lib/player-transliteration.mjs`는 기존 명단의 동일 철자·이름 구성요소 발음을 재사용하고 나머지 라틴 철자는 결정적인 음역 초안으로 변환한다. 발음 언어와 실제 발음을 확정하는 도구는 아니다. 결과는 기존 `player_names.source='transliteration'`에 저장하고 확인된 공개 이름으로 표시하지 않는다. 한글 원어는 그대로 사용한다. 지원하지 않는 문자와 기존 비한글 수동 표기는 누락 사유로 보고하며 성공으로 숨기지 않는다.

`scripts/lib/missing-korean-names.mjs`는 `players.name_ko`와 `player_names.display_name`을 함께 검사한다. 기존 서비스 역할 전용 `kickx_apply_korean_catalog` RPC가 ID·원어명·생년월일을 다시 확인하고 비어 있는 이름만 삽입한다. 이름 테이블 트리거로 `players.name_ko`도 채운다. 이름 테이블에 한글명이 있는데 컬럼만 비어 있으면 동일 값·source 조건으로 트리거를 재실행해 source를 보존하며 복구한다. 새 SQL은 필요 없다. 기존 한글 컬럼 마이그레이션이 없는 DB에는 기존 이름 테이블 호환 경로와 스키마 상태를 명시한다.

`scripts/apply-korean-names.mjs`는 원래 명단 적용 후 신규 누락을 채운다. 기본 실행은 읽기 감사, `--apply`는 적용, `--report=파일.json`은 전후 집계 보고서다. 미해결 이름 또는 컬럼 동기화 누락이 남으면 적용 실행은 실패 상태로 표시한다. GitHub의 `Apply Korean catalog names` 작업이 읽기 감사→적용→보고서 보관을 실행한다. 가격 계산 작업 전체를 이름 적용 때문에 다시 실행하지 않는다.

자동 수집기의 이름 단계는 최대 500개 빈 이름을 먼저 채우고 기존 Wikidata 인물 검증을 최대 100명 실행한다. 생년월일·이름·공개 한글명을 모두 검증한 결과만 `wikidata`로 개선하며 수동 이름은 보호한다. 입력이 바뀌면 재검사하고 기존 검사 캐시는 유지한다.

검증은 음역 입력·지원하지 않는 문자·생년월일 없는 선수·소속 없는 선수·수동 이름 경합·반복 적용·컬럼 동기화·실제 SQL 삽입 보호를 포함한다. 운영 적용 수치는 해당 GitHub 작업의 `korean-name-coverage` 보고서와 로그를 기준으로 확인한다.

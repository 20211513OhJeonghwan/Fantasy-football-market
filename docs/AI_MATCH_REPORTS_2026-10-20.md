# 경기별 AI 리포트

## 사용자 동작

- 선수 상세 → 최근 경기 → 각 전적의 **리포트** 버튼. 가치 분석 탭에서도 최근 경기로 진입한다.
- 경기 종료와 Performance·가격 산정이 모두 완료돼야 한다. `ready`와 `provisional`을 지원하고, 잠정 여부를 표시한다.
- 로그인한 회원이 처음 열면 없는 설명을 생성한다. 생성된 설명은 모든 이용자가 공유하며 비로그인 이용자도 읽을 수 있다.
- API 키 미설정·무료 한도 소진·모델 장애 시에도 실제 산정 숫자와 주요 가점·감점, 목표가, 변동 전후 가격을 볼 수 있다. 이 부분은 **산정 요약**으로 표시하며 AI가 쓴 글로 표시하지 않는다.
- AI는 점수와 가격을 계산하지 않는다. 한국어로 경기력·가치 변동의 두 짧은 문단만 설명한다. 정확한 숫자는 DB 값을 별도 표시하고, AI 본문에 숫자를 쓰면 응답을 거부한다.

## 모델 선정과 설정

2026-10-20 공식 문서 확인 결과 Gemini 3.5 Flash-Lite의 표준 API 입력·출력에 무료 티어가 있다. 신규 프로젝트 사용이 제한되는 구형 2.5 모델 대신 현재 안정 모델 `gemini-3.5-flash-lite`를 기본값으로 사용한다. 무료 모델을 찾았으므로 OpenAI 유료 호출로 자동 전환하지 않는다.

- 가격: https://ai.google.dev/gemini-api/docs/pricing
- 모델: https://ai.google.dev/gemini-api/docs/models/gemini-3.5-flash-lite
- 실제 계정 한도: https://ai.google.dev/gemini-api/docs/rate-limits
- API 키 발급: https://aistudio.google.com/api-keys

무료 티어는 무제한이 아니다. 프로젝트·계정별 RPM/TPM/RPD는 AI Studio에서 확인해야 한다. 무료 티어의 제출 내용은 Google 제품 개선에 사용될 수 있으므로 유저·보유 자산·커뮤니티 내용은 전달하지 않는다. 공개 경기의 산정 숫자와 짧은 지표명만 전달한다.

운영 활성화 순서:

1. `supabase/migrations/20261020062505_match_ai_reports.sql` 전체를 Supabase SQL Editor에서 한 번 실행한다.
2. Vercel의 해당 프로젝트 서버 환경변수에 `GEMINI_API_KEY`와 `SUPABASE_SERVICE_ROLE_KEY`를 설정하고 재배포한다. GitHub Actions의 비밀변수는 Vercel에 자동 공유되지 않는다.

Google AI Studio에서 **Free tier 프로젝트의 키**를 사용한다. 이 기능을 위해 결제 계정을 연결할 필요는 없다. 키를 저장소나 채팅에 올리지 않는다. 선택 환경변수 `GEMINI_REPORT_MODEL`의 기본값은 `gemini-3.5-flash-lite`다.

이 작업 환경에는 Gemini 키가 없으므로 실제 공급자 호출 검증은 키 설정 뒤 필요하다. 키가 없는 상태에서는 외부 모델 호출·생성용 DB 쓰기가 발생하지 않는다.

코드는 PR #23으로 main에 병합했고 Vercel 배포 성공을 확인했다. 운영 DB 적용 도구는 `Invalid or expired requestState` 오류를 두 번 반환했고, 이후 읽기 검사에서도 마이그레이션과 리포트 RPC가 없음을 확인했다. 따라서 운영 DB는 아직 미적용이다. 배포된 리포트 GET도 서버용 Supabase 키 설정을 요구하는 503을 반환했다. 위 두 설정을 완료하기 전에는 운영 AI 리포트가 활성화된 상태가 아니다.

## 전송량과 DB 크기 제한

| 항목 | 구현 |
| --- | --- |
| 페이지 최초 로딩 | 리포트 조회·생성 요청 없음. 기존의 비어 있던 선수 전체 분석 조회도 제거 |
| 생성 시점 | 종료·산정 완료 경기에서 버튼을 연 회원의 요청만 처리 |
| 공유 단위 | 선수·경기 한 쌍당 한 행. 유저별 복제 없음 |
| 원본 데이터 | BSD 재호출 없음. 원본 JSON, 전체 가격 이력, 경기 사건, 계산 리비전 전체를 읽거나 복사하지 않음 |
| DB 조회 | 대상 선수·경기 PK 및 인덱스로 한정한 RPC. 리포트 열기에만 작은 DTO 반환 |
| 캐시 | 공개 GET CDN 캐시 완료 60초/미완료 10초. 브라우저 메모리 완료 캐시 60초·최대 40건 |
| 동시 요청 | 브라우저 진행 중 요청 공유 + DB의 45초 생성 권한. 이미 작성 중이면 모델 재호출 없음 |
| 자동 갱신 | 주기적 폴링·Realtime 구독·전체 선수 일괄 생성 없음 |
| 모델 호출 상한 | 서비스 전체 UTC 하루 100회, 분당 4회. 회원별 당일 신규 캐시 요청도 제한. 공급자 실제 한도는 별도 적용 |
| 실패 재시도 | 같은 입력에 최대 2회/24시간. 일반 실패 5분, 공급자 429는 1시간 대기. 즉시 자동 재시도 없음 |
| 모델 출력 | 최대 650 출력 토큰. 두 문단 각 220자 이하·저장 본문 합계 1,600바이트 이하 |
| 캐시 보관 | 경기별 최대 3,000행. 새 생성 때 오래된 완료/만료 항목 교체. 90일 지난 항목은 한 번에 최대 100행 정리 |
| 저장량 | 최대 본문 합계 4.8MB. 행·인덱스·Postgres 여유 공간은 별도이며 총 DB 물리 용량 4.8MB를 보장하는 뜻은 아님 |
| 별도 로그 | 프롬프트·원본 모델 응답·공급자 오류 메시지·요청별 감사 로그를 저장하지 않음. 일·분 사용량은 기존 정책 행의 작은 JSON에 누계만 유지 |
| 테이블 수 | 새 테이블 없음. 기존 `player_analyses`를 확장하며 예전 선수 단위 행도 보존 |

캐시 정리로 오래된 설명이 없어지면 필요한 때 다시 생성할 수 있다. 경기 기록·거래·가격 이력은 삭제하지 않는다. DELETE 뒤 물리 파일이 즉시 줄어드는 것은 아니며 Postgres가 빈 공간을 재사용한다.

## 정정·권한 처리

- 캐시 해시는 해당 경기의 설명용 사실과 프롬프트 버전으로 만든다. 전체 선수 계산 해시·시간 변경만으로 재생성하지 않는다.
- 점수·기여 항목·가격 등이 실제로 정정되면 기존 설명을 숨기고 **같은 행을 교체**한다. 완료 응답 저장 전 입력 해시와 생성 토큰을 다시 확인한다.
- 가격 산정 입력 해시와 Performance 입력 해시가 다르면 이전 가격을 새 점수와 결합하지 않는다.
- 공개 캐시는 정정 반영에 최대 약 60초 지연이 있을 수 있다. 이미 열린 화면은 다시 열어 확인한다.
- 생성 POST는 같은 출처와 검증된 로그인·프로필을 요구하고 이용 제한 계정은 차단한다.
- DB RPC 4개는 `SECURITY INVOKER`이며 `service_role`만 실행한다. 브라우저가 직접 생성 권한을 잡거나 사용량 누계를 변경할 수 없다.
- 기존 분석 테이블의 RLS와 선수 단위 레거시 읽기를 유지한다. 경기 리포트의 내부 토큰·요청자·해시는 공개 API 응답에 포함하지 않는다.

## 주요 파일 / Claude 디자인 인계

- `components/kickx/match-report.tsx`: 기존 접근성 모달을 사용한 리포트 화면. 상단 수치 카드, 잠정 표시, 기여 항목, AI 설명/산정 요약, 장애·미로그인 상태를 유지한다.
- `components/kickx/players.tsx`: 전적 표 버튼 및 가치 분석 탭 진입점.
- `app/styles/pages.css`: `.report-*`, `.match-report` 클래스. 모바일 390px에서는 수치 카드를 한 열로 배치한다.
- `server/kickx/match-reports.ts`: 읽기·생성 조율 및 공개 DTO 제한.
- `server/kickx/report-model.ts`: 공급자 호출·짧은 프롬프트·응답 검증. 공급자 SDK 추가 없이 REST로 호출한다.
- `lib/kickx/match-report.ts`: 공개 DTO.
- `app/api/kickx/players/[id]/matches/[fixtureId]/report/route.ts`: GET/POST.
- `supabase/migrations/*_match_ai_reports.sql`: 캐시·권한·사용량·정정 대응.

디자인을 변경할 때 모달을 열기 전 요청하지 않는 동작, 같은 경기 재열기 캐시, AI 작성 여부 구분, 실제 계산 숫자, 잠정 상태를 유지한다. 자동 폴링이나 선수 목록 전체의 리포트 미리 읽기를 추가하지 않는다.

## 검증

- 모델/API 단위 테스트: 프롬프트 최소화, 실제 숫자 덮어쓰기 방지, 공급자 한도·오류·잘린 출력, 중복 요청, 권한·출처 검사.
- SQL 통합 테스트: 같은 경기 재사용, 생성 권한, 잘못된 토큰, 실제 정정 무효화, 입력 해시만 바뀐 재산정 재사용, 한도·보관 상한, 구형 행 보존, 익명/회원 권한 분리.
- 브라우저 테스트: 최초 로딩 요청 없음, 버튼에서 생성, 재열기 추가 호출 없음, 모바일 모달, Escape 닫기.
- 실제 모델의 한국어 품질과 계정 무료 한도는 운영 키 설정 후 확인한다.
- 최종 검증: 단위 테스트 **188개**, 실제 PostgreSQL **17**의 전체 마이그레이션·권한 테스트, 데스크톱 **1440px**·모바일 **390px** 브라우저 테스트, lint·빌드 모두 통과. CI: https://github.com/hyun1290/kick-x-test/actions/runs/39382813857

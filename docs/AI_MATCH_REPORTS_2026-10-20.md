# 경기별 AI 리포트

## 현재 동작

- 로그인하고 프로필 설정을 마친 회원에게만 리포트 버튼과 모달을 표시한다. GET/POST 모두 서버에서 로그인을 확인한다. 비로그인 상태나 로그아웃 후에는 리포트 요청을 시작하지 않는다.
- 종료된 경기 중 별도의 가격 변동 결과가 있고, 출전 시간과 Performance가 반영된 경기만 버튼을 표시한다. 초기 가격 산정에 이미 쓰인 과거 경기는 버튼을 숨긴다. 표시 여부는 선수 상세에서 이미 조회하는 가격 이력·경기 상태로 판단하며 경기별 추가 조회를 하지 않는다.
- 모달의 노란 헤더에 경기 날짜와 상대를 표시한다. 본문의 “경기별 Performance와 가치 변동” 문구와 장문의 잠정 안내를 제거했다. 점수 카드의 짧은 “잠정 산정” 표시는 유지한다.
- 상단의 Performance와 실제 전후 가격·변동률은 DB 값이다. 아래 AI 설명은 **경기력만** 다룬다. AI 가치 변동 설명과 목표가·가중 점수 설명 영역은 제거했다.
- AI는 가장 큰 가점, 출전 시간과 공격·수비 기여의 비중, 감점 영향을 연결해서 보통 세 문장부터 다섯 문장으로 설명한다. 최대 420자이며 입력 기록이 적으면 짧게 쓴다. 잠정 점수·미확인 통계·추후 정정에 대한 문구는 생성 지시에서 제외했다.
- 입력에 없는 경기 장면이나 전술·부상·기록을 추측하지 않는다. AI가 숫자를 만들지 않도록 정확한 점수는 별도 카드와 기여 항목으로 표시한다.
- 생성이 실패해도 이미 읽은 점수와 변동 수치는 유지하고, 자동 재호출 없이 수동 재시도를 제공한다.

## 재사용과 사용량

**버튼을 누를 때마다 생성하지 않는다.** 선수·경기 한 쌍당 저장된 설명을 모든 회원이 공유한다. 기존 설명이 있으면 읽기만 하고 공급자를 호출하거나 같은 본문을 다시 쓰지 않는다.

| 항목 | 제한 및 동작 |
| --- | --- |
| 최초 페이지 로드 | 리포트 조회·생성 없음 |
| 브라우저 캐시 | 완성된 설명 60초, 최대 40건; 진행 중 같은 요청도 공유 |
| HTTP 캐시 | 로그인 검증 후 private, no-store; 공개 CDN 응답으로 인증을 건너뛰지 않음 |
| DB 캐시 | 선수·경기당 한 행. 유저별·재시도별 복제 없음 |
| 정정 | 점수·출전 시간·기여 항목이 실제 바뀔 때만 AI 입력 해시 변경 |
| 가격만 변경 | 화면에는 최신 수치, 기존 경기력 설명 재사용. 모델 재호출 없음 |
| 형식 변경 | `match-report-performance-v2`; 기존 설명은 다음 회원 요청 때 같은 행에서 한 번 갱신. 일괄 재생성 없음 |
| 전체 모델 호출 | UTC 하루 100회, 분당 4회; 회원별 당일 신규 캐시 요청도 제한 |
| 생성 권한 | 45초 동안 중복 생성 방지 |
| 실패 | 같은 입력 최대 2회/24시간. 일반 실패 5분, 공급자 429는 1시간 대기 |
| 출력 | 최대 650 출력 토큰, 본문 최대 1,600바이트, 응답 수신 최대 16KB |
| DB 보관 | 경기별 최대 3,000행. 90일 초과 행은 새 생성 시 최대 100행씩 정리 |
| 최대 본문 | 합계 4.8MB 이하. 행·인덱스·Postgres 여유 공간은 별도 |
| 별도 저장 | 프롬프트·원본 공급자 응답·요청별 감사 로그·원본 경기 JSON 복제 없음 |
| 데이터 공급자 | BSD 추가 호출 없음. 저장된 경기 결과만 사용 |

캐시가 정리됐거나 경기력 입력이 정정된 경우에는 필요할 때 다시 생성할 수 있다. 동일한 설명을 버튼 클릭마다 생성하는 구조는 아니다. 가격 계산식과 데이터 갱신 주기는 변경하지 않았다.

## 모델과 환경변수

기본 모델은 `gemini-3.5-flash-lite`이며 서버 환경변수 `GEMINI_API_KEY`와 `SUPABASE_SERVICE_ROLE_KEY`를 사용한다. 선택 환경변수 `GEMINI_REPORT_MODEL`로 모델을 지정한다. 키를 브라우저·저장소·채팅으로 전달하지 않는다. 무료 티어의 실제 한도는 Google AI Studio 계정에서 확인한다. 자동으로 유료 모델로 전환하지 않는다.

- 가격: https://ai.google.dev/gemini-api/docs/pricing
- 모델: https://ai.google.dev/gemini-api/docs/models/gemini-3.5-flash-lite
- 계정별 한도: https://ai.google.dev/gemini-api/docs/rate-limits

AI에 보내는 입력은 점수·출전 시간·기여 항목뿐이다. 선수 이름·상대·유저·보유 자산·커뮤니티·가격 이력을 보내지 않는다. 공급자는 REST로 한 번 호출하며 서버 제한 시간은 12초다.

## DB 적용과 권한

2026-10-20 운영 DB에 `20261020080737_performance_only_match_reports.sql` 적용 성공을 확인했다. 이전 기본 리포트 스키마와 safeupdate 수정이 적용된 프로젝트를 위한 추가 마이그레이션이다. 신규 환경에서는 저장소의 전체 마이그레이션을 순서대로 적용한다.

기존 `player_analyses`와 `kickx_policy`를 재사용한다. 새 테이블은 없으며 일·분 사용량은 단일 정책 행의 JSON 누계로 유지한다. 갱신은 `WHERE id=true`를 명시해 운영 safeupdate 보호 설정과 호환된다. RPC는 SECURITY INVOKER이며 service_role만 실행할 수 있다. 기존 레거시 분석 행·RLS·캐시 보관 상한을 유지한다.

형식 변경 마이그레이션이 아직 없는 환경에서는 앱이 기존 형식의 AI 본문을 숨기고 모델 호출을 시작하지 않는다. 버전은 API 공개 DTO에 노출하지 않는다.

## Claude 디자인 인계

- `components/kickx/match-report.tsx`: 기존 Modal 사용. 경기 날짜는 노란 헤더의 eyebrow, 경기 상대는 제목에 표시한다. 실제 점수·가격 수치, 경기력 설명, 기여 항목과 장애 상태를 유지한다. AI 가치 설명을 다시 추가하지 않는다.
- `components/kickx/players.tsx`: 최근 경기 표와 가치 분석 탭 모두 같은 로그인·reportAvailable 조건으로 버튼을 표시한다. 초기 가격용 경기와 비로그인 화면에 비활성 버튼을 남기지 않는다.
- `server/kickx/catalog-pages.ts`: 추가 리포트 조회 없이 기존 가격 결과와 종료 상태로 reportAvailable을 계산한다.
- `server/kickx/report-model.ts`: 경기력만 포함하는 프롬프트, 출력 스키마와 검증.
- `server/kickx/match-reports.ts`: 로그인 검증, 공급자 호출 조율과 공개 DTO 제한.
- `supabase/migrations/20261020080737_performance_only_match_reports.sql`: 새 형식, 저장·재사용 및 경기력 입력만 비교하는 해시.

디자인 변경 시 버튼을 열기 전 요청하지 않는 동작, 재열기 캐시, 미로그인·과거 경기 숨김, AI 작성 여부와 실제 숫자를 유지한다. 자동 폴링이나 선수 목록 전체 리포트 미리 읽기는 추가하지 않는다.

## 검증

단위 테스트 191개, 전체 SQL 통합 테스트, lint와 빌드 통과. SQL 검증은 이전 형식의 지연 갱신, 같은 행 재사용, 가격만 변경할 때 재생성 방지, 실제 정정·토큰·한도·권한·캐시 상한을 포함한다. 브라우저 회귀 테스트는 헤더 날짜, 가치 설명 제거, 재열기 재사용, 생성 실패 시 숫자 유지, 비로그인·초기 가격 경기 버튼 숨김과 요청 없음, 모바일 표시를 확인한다. 실제 Gemini 새 설명의 문장은 다음 회원 생성 요청에서 확인한다.

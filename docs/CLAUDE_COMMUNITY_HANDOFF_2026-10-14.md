# Claude 디자인 인계 — 선수·구단 커뮤니티 피드 개편

## 이번 작업의 기준

저장소 https://github.com/hyun1290/kick-x-test , 운영 https://kick-x-test.vercel.app/ . 최신 main을 받은 뒤 이 문서와 실제 코드를 먼저 읽는다. 이번 커뮤니티 작업은 이 문서가 이전 `CLAUDE_DESIGN_HANDOFF_2026-10-12.md`의 제목 중심 목록·커뮤니티 첫 화면 설명보다 최신이다.

사용자는 토스증권 커뮤니티에서 참고한 본문 중심 피드와 간편 참여를 원하지만, **선수 커뮤니티와 구단 커뮤니티는 분리**하라고 확정했다. 두 종류의 글을 한 피드에 섞거나 첫 진입을 한 종류로 자동 전환하지 않는다. 선수는 경기력·가격·거래 판단, 구단은 팬의 경기·구단 대화가 중심이다. 토스증권을 그대로 복제했다고 설명하지 않는다.

이번 코드는 실제 API를 사용하는 기능 구현과 기본 배치다. Claude는 이 기능을 유지하면서 타이포그래피·여백·카드·작성창·우측 보조 정보·모바일 동작을 디자인한다. 현재 앱의 Yellow Playbook 토큰을 기준으로 시작하고, 사용자 지시 없이 새 브랜드·테마를 확정하지 않는다.

## 구현된 동작

| 주소 | 역할 |
|---|---|
| `/community` | 선수·구단 두 진입 카드. 글을 합친 피드 없음 |
| `/community/players` | 선수 이야기 피드, 보유 선수 바로가기, 선수 탐색 |
| `/community/clubs` | 구단 이야기 피드, 내 응원 구단 바로가기, 5대 리그 구단 탐색 |
| `/community/players/[playerId]` | 해당 선수에 고정된 작성창·피드·가격/Performance 요약 |
| `/community/clubs/[teamId]` | 해당 구단에 고정된 작성창·피드·소속 선수 링크 |
| `/players/[id]`의 커뮤니티 탭 | 해당 선수 피드와 작성창을 선수 정보 안에서 사용 |
| `/community/posts/[postId]` | 상세, 전체 댓글·답글, 본인 수정·삭제, 신고 |
| `/community/write` | 제목을 선택 입력하는 기존 긴 글 편집 화면 |

- 피드 카드는 작성자·시간·대상·주제·본문·체결 거래 첨부·공감·댓글을 표시한다. 긴 본문은 400자 미리보기 후 **더 보기/접기**로 읽는다. 카드 전체를 링크로 감싸지 않아 텍스트 선택과 버튼 사용이 가능하다.
- 간편 작성창은 현재 커뮤니티 종류에 고정된다. 선수 허브에서는 이름 검색으로 선수를 선택한다. 구단 허브에서는 본인 응원 구단에 게시한다. 개별 라운지와 선수 상세 탭에서는 대상까지 고정된다.
- 기본 주제는 자유. 제목 없이 작성할 수 있으며, 제목·주제·본인 체결 거래 첨부는 펼쳐서 추가한다. 긴 글 편집 화면도 유지한다.
- 제목 없는 글은 기존 DB 계약을 유지하기 위해 서버가 본문 첫 부분으로 제목을 만든다. 피드에서는 이를 별도 제목처럼 반복하지 않는다. 실제 선택 제목은 표시한다. 기존 글은 삭제·변환하지 않는다.
- 본문은 기존 10~3,000자, 선택 제목은 입력할 경우 2~80자다. 새 SQL이나 DB 컬럼 추가는 없다.
- 피드에서 공감을 켜거나 끄고 댓글을 읽고 작성할 수 있다. 댓글 미리보기는 현재 댓글 페이지의 마지막 3개다. 전체 댓글·답글·수정·삭제·신고는 글 상세에서 사용한다.
- 저장·공감 실패를 성공처럼 표시하지 않는다. 저장 실패 시 본문을 보존하고, 같은 내용을 재시도할 때 동일한 requestId를 사용한다. 입력을 바꾸면 새 requestId를 사용한다. 처리 중 중복 제출을 막는다.
- 검색·주제·최신순/공감순·페이지 이동·빈 결과·오류 재시도 동작이 있다. **공감순은 누적 공감**이며 최근 인기 알고리즘으로 표시하지 않는다.

## 반드시 유지할 권한과 데이터 계약

- 공개 글은 누구나 읽는다. 선수 글·댓글은 프로필이 있는 회원, 구단 글·댓글은 해당 구단의 응원 팬만 작성한다. 공감·신고는 로그인 필요. 이용 제한 검증은 기존 서버/DB가 수행한다.
- 거래 첨부는 본인 거래만 가능하며, 이름·금액·일시는 체결 당시 DB 기록이다. 현재 가격이나 다른 사람의 거래를 첨부했다고 꾸미지 않는다. 개인 지갑·보유액·수익률을 공개 피드에 붙이지 않는다.
- 글 수정으로 scope나 target을 바꾸는 요청은 서버가 409로 거절한다. 수정·삭제의 revision 충돌 처리와 DB 작성자 검증을 유지한다.
- 읽기 API에는 항상 `scope=player` 또는 `scope=club`을 전달한다. 개별 라운지에는 `target`도 전달한다. 범위 미지정 읽기는 선수 피드 기본값이다. `scope=all`은 거절한다. 저장은 `community_posts.scope`와 target으로 구분한다.
- `/api/kickx`에 내려오는 전체 글 일부를 선수 상세 커뮤니티 전체 목록으로 사용하지 않는다. 탭은 해당 선수용 페이지 API를 조회한다. 선수 검색도 전체 카탈로그 페이지 API를 사용한다.
- 텍스트는 React 일반 텍스트로 렌더한다. HTML 본문을 직접 주입하지 않는다. 선수·구단 이름 대신 ID로 대상을 연결한다.

## 시각 작업 우선순위

1. 본문이 주인공인 피드 카드: 작성자/시간은 작게, 대상은 명확히, 반응은 읽기 흐름 아래로 배치한다.
2. 간편 작성창: 열기 전의 가벼운 참여 유도와 펼친 뒤의 집중 상태, 저장 중/실패/권한 없음 상태를 다듬는다. 선택 제목·거래 첨부를 필수 입력처럼 보이게 하지 않는다.
3. 허브·라운지·선수 상세 탭의 일관성: 같은 Feed를 쓰는 세 공간에서 폭·중첩 패널·여백을 조절한다. 선수/구단 종류가 항상 명확해야 한다.
4. 탐색/보유 선수/응원 구단 바로가기와 우측 보조 영역의 정보량을 줄인다. 피드가 구단 목록 아래로 밀리지 않도록 한다.
5. 1440px와 390px에서 긴 이름·영문·줄바꿈·긴 URL·거래 금액·본문 펼침·열린 댓글·작성 오류를 확인한다. 전체 문서 가로 넘침, 작은 터치 영역, 포커스 소실을 만들지 않는다.

## 이번에 구현하지 않은 후속 기능

팔로우·사용자 공개 프로필·언급·알림·북마크·사용자 차단·보유 인증 배지·손익 공개 설정·선수 가격/경기 점수 스냅샷 첨부·시간 감쇠 인기순·이미지 업로드는 이번 범위에 없다. 본인 거래 첨부만 기존 실제 계약을 재사용한다. 후속 기능을 디자인할 때 동작하는 버튼·알림 숫자·인증 배지처럼 운영 UI에 넣지 않고, 별도 제안으로 표시한다. 관심 선수/보유 선수만으로 피드를 필터링하는 서버 기능도 아직 추가하지 않았다.

## 검증과 인수 후 작업

`npm run lint`, `npm test`, `npm run build`와 CI의 기존 DB/RLS 검사, `tests/browser-smoke.mjs`를 확인한다. 새 서버 검사에는 scope 필터·선택 제목·응원 팬 권한·수정 대상 변경 차단이 포함된다. 새 브라우저 시나리오는 선수/구단 피드 격리, 제목 없는 작성, 실패 시 본문 및 재시도 UUID 유지, 피드 공감·댓글, 다른 구단 팬 작성 제한, 선수 상세 탭, 데스크톱/모바일 폭을 다룬다. 브라우저 대역 계약 검사와 실제 Google OAuth 계정의 운영 쓰기 검증은 구분한다. 운영 DB에 검사용 게시글을 임의로 만들지 않는다.

GitHub Actions의 `kickx-browser-checks` 산출물에 `community-entry`, `community-players`, `community-clubs`, 개별 라운지, `community-player-tab` 스크린샷이 있다. Claude는 디자인 후 같은 흐름을 다시 검사하고 변경 파일·검증·남은 기능을 최종 보고한다. 경기 수집·가격 산정 전체 작업을 디자인 검증 때문에 다시 실행하지 않는다.

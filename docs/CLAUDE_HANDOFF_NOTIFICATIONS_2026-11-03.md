# Claude 인계: 알림함과 선수 시장 기본 표시

## 이번 변경

- 헤더의 프로필 메뉴 왼쪽에 편지 모양 알림함을 추가했다. 읽지 않은 알림이 있으면 우측 상단에 빨간 점을 표시한다.
- 알림 대상은 현재 보유한 선수다. 관심 선수 전체를 대상으로 하지 않는다.
- 실제 발행 가격이 바뀌면 변경 전후 가격을 알린다. 초기 가격 등록·가격 보류·동일 가격 갱신에는 알림을 만들지 않는다.
- 보유 선수 소속 구단의 5대 정규 리그 경기 시작 90분 전부터 경기 알림을 만든다. 선발 출전 확정을 의미하지 않는다.
- 스쿼드 상단의 `보유 선수 경기 알림` 스위치로 경기 알림 전체를 켜고 끈다. 서버에 저장해 다음 로그인에도 유지한다. 가격 알림에는 영향을 주지 않는다.
- 알림은 14일간 보관한다. 기한이 지나면 조회에서 즉시 제외되고 정기 작업이 삭제한다.
- 개별 알림 클릭과 `모두 읽음`을 지원한다. 가격 알림은 선수 상세, 경기 알림은 구단 상세로 이동한다.
- 구단 커뮤니티의 `게시판 구단` 드롭다운을 삭제했다. 기존 응원 구단 버튼과 전체 게시글은 유지한다.
- 선수 시장은 카드형을 기본으로 연다. 반응형 열 수에 맞춰 한 페이지에 두 줄을 표시하고 번호·직접 입력 페이지 이동과 목록 전환은 유지한다.

## 디자인 수정 시 지킬 동작

1. 편지 아이콘은 프로필 버튼 왼쪽에 둔다. 빨간 점은 실제 읽지 않은 알림 여부를 사용하며 예시 점을 상시 표시하지 않는다.
2. 알림함에서 선수 이름, 가격 전후 또는 경기 구단·시작 시각, 알림 시각을 구분해 읽을 수 있게 한다. 긴 이름과 모바일 폭을 확인한다.
3. 비로그인 상태에는 알림함과 경기 알림 설정을 표시하지 않는다. 오류·로딩·빈 상태·이전 알림 더 보기를 구분한다.
4. 키보드 Escape와 바깥 클릭으로 닫을 수 있어야 한다. 읽음 처리는 서버 성공 후 반영한다.
5. 경기 알림을 끄더라도 과거 알림은 남아 있다. 새 경기 알림 생성만 중지한다. 이미 시작한 경기는 뒤늦게 알리지 않는다.
6. 카드형 두 줄과 페이지 크기의 연결을 유지한다. 목록형은 12명이며 표시 방식 전환 시 보던 위치를 유지한다.

## 구조와 사용량

- 화면: `components/kickx/notifications.tsx`, `app/styles/notifications.css`, 헤더 `shell.tsx`, 설정 `squad.tsx`.
- API: `/api/kickx/notifications`의 GET/PUT. 로그인 사용자 본인의 RPC만 호출한다. 응답은 private/no-store다.
- 저장: `public.user_notifications`와 `profiles.match_notifications`. 알림 본문·사진·선수 통계를 복제하지 않고 식별자와 가격·시각만 저장한다.
- 가격 알림은 `player_market_snapshots`의 확정 가격 변경 트리거로 만든다. 경기 알림·삭제는 `kickx-notifications`가 매분 실행한다. BSD·AI API 추가 호출은 없다.
- 헤더는 로그인 상태에서만 미확인 여부와 설정의 작은 응답을 60초마다 확인한다. 백그라운드 탭은 정기 조회를 멈춘다. 목록은 알림함을 열 때 20건씩 가져오며 커서 페이지를 사용한다.
- 본인 행만 읽고 `read_at`만 바꾸도록 RLS와 컬럼 권한을 제한했다. 일반 사용자는 알림 생성·가격 내용 변경을 할 수 없다.
- 중복 키로 같은 경기·같은 가격 발행의 재실행을 방지한다. 14일 만료 삭제는 한 번에 최대 2,000건이며 이 알림 작업의 cron 실행 로그도 하루만 보관한다.
- 마이그레이션: `supabase/migrations/20261103123728_user_notifications.sql`. 운영 DB에 적용했으며 정기 작업 성공과 권한을 확인했다. 과거 알림을 대량 생성하지 않았다.

## 기존 작업 보존

개인 main의 Claude 변경 `db87560`에 있던 아바타, 차트, 잔디·유니폼, 게시판 구단 표시, 점수 막대 디자인을 보존했다. 작업 도중 팀원 main에 추가된 `d5be9d2`의 스쿼드 편집, 페이지 보정, 검색 검증, 접근성, 운영 정책 표시 수정도 합쳤다.

Claude의 기존 `profiles.avatar` 마이그레이션은 운영 적용 확인이 완료되지 않았다. 현재 코드의 미적용 시 대체 표시·저장 호환 처리를 유지한다. 이번 알림 기능은 이 컬럼에 의존하지 않는다.

## 선수 사진 조사

현재는 이미 BSD의 `sor=true&bg=transparent` 컷아웃 옵션을 사용한다. 공급자는 Cut-Out 매핑이 없으면 기본 이미지로 대체한다고 명시한다. 확인한 표본은 원본·컷아웃 모두 150×150이라 확대하면 화질과 흰 테두리 문제가 드러난다.

CSS만으로 원본에 없는 세부 묘사를 복원하거나 잘못 제거된 경계를 정확히 복구할 수는 없다. 표현 개선은 과도한 확대를 줄이고 작은 원본과 큰 컷아웃의 표시를 구분하는 방향이 적절하다. 품질을 확실히 개선하려면 사용 권한을 확인한 고해상도 컷아웃 원본과 선수별 이미지 대체 경로가 필요하다. 이번에는 선수 얼굴을 AI로 재생성하거나 전체 사진을 일괄 교체하지 않았다.

## 검증

- 251개 단위 검사 통과. 새 알림 API 검사는 로그인·본인 식별·입력 제한·외부 출처 쓰기 차단을 포함한다.
- 전체 마이그레이션 기반 DB 검사 통과. 보유자별 전달, 중복 방지, 보류 가격 제외, 본인 읽음 처리, 경기 알림 끄기, 만료 숨김·삭제, 비로그인 접근 제한을 검증했다.
- 운영 DB에서 RLS·컬럼 권한과 매분 알림 작업의 성공을 확인했다. 테스트 사용자를 운영 DB에 추가하지 않았다.
- 프로덕션 빌드·타입 검사·수정 파일 ESLint를 통과했다.
- PC 1440px·모바일 390px에서 아이콘 위치, 빨간 점, 20건 단위 이전 알림 조회, 모두 읽음, Escape 닫기, 스쿼드 설정의 새로고침 유지, 드롭다운 제거, 카드형 기본값, 비로그인 숨김을 브라우저로 확인했다. 화면 검사는 별도의 테스트 응답으로 수행했다.
- 팀원 main의 스쿼드 편집·페이지 보정·검색·접근성 관련 9개 UI 회귀 검사도 통과했다.

사용자가 제공한 2026-27 시즌 5개 리그 엑셀의 첫 번째 전체 선수 시트에서 이름 자료만 추출했다. 원본 파일명, SHA-256, 시트, 행 번호, 리그의 원래 식별 ID는 `data/localization/players.workbook.ko.json`에 보관한다. 원본 엑셀은 수정하지 않는다.

## 연결과 보존 규칙

- FPL, DFL, 리그 공식 ID는 BSD ID와 다른 체계다. 숫자가 같아도 연결하지 않는다.
- 영문명과 생년월일이 일치하는 BSD 선수를 우선 연결한다. 악센트·공백·하이픈 차이를 정규화하며, 이적한 선수는 구단이 달라도 이름과 생년월일로 연결할 수 있다.
- 생일이 없는 경우 정확한 이름과 구단이 함께 일치해야 한다. 생일 상충, 동명이인, 확인 불가, 한글명 빈칸은 기존 값을 유지한다.
- 자동 연결에서 보류된 건은 별도 `identity_overrides`에 개별 검수한 교차표로 기록한다. 같은 전체 이름과 같은 구단으로 확인한 생일 충돌은 기존 DB ID·생일·구단과 엑셀의 이름·생일·구단을 모두 고정한 뒤 이름만 변경한다. 본명/등록명 차이는 생일·구단 및 필요한 구단/협회 원문으로 대조한다. 교차표의 어느 식별 정보라도 바뀌면 다시 보류한다.
- 전체 이름의 단어 또는 이니셜 차이는 생년월일까지 일치할 때만 허용한다. 성씨 단독, 유사 문자열, 추측 번역으로 연결하지 않는다.
- 기존 수동 수정은 보존한다. 반영하는 자료는 `player_names.source=manual`로 저장하므로 자동 Wikidata 번역과 빈 이름 보충이 덮어쓰지 못한다. 기존 별칭과 이전 한글 이름도 가능한 한 검색 별칭으로 유지한다.
- 변경 직전 선수 식별 정보를 재확인하고, 기존 이름·출처·갱신 시각을 비교하여 동시 수정이 있으면 건너뛴다. 같은 BSD 선수에 서로 다른 한글명이 연결되면 자동 반영하지 않는다.
- `player_names`의 기존 트리거가 `players.name_ko`를 함께 갱신한다. 새 SQL 적용은 필요 없다. 등번호·소속·생일·가격·경기 데이터는 이 작업에서 갱신하지 않는다.

## 실행

`node scripts/apply-workbook-player-names.mjs --report=workbook-names-before.json`으로 사전 점검한다. `--apply`를 추가하면 실제 저장하고 DB의 표시 이름·수동 출처·`players.name_ko`를 다시 읽어 확인한다.

`Apply supplied Korean player names` GitHub Actions는 관련 코드·자료의 main 변경과 수동 실행에 대응한다. 공유 DB에 중복 반영하지 않도록 원본 저장소에서만 실행한다. 같은 이름 작업의 동시 실행은 직렬화한다. 구간별 변경 감사 기록과 적용 전후 JSON 보고서를 남긴다. 보고서의 `skipped`에는 빈칸, DB에 없는 선수, 생일 상충 및 추가 검수 대상이 담긴다.

## 화면 및 디자인 인계

화면 구조 변경은 없다. 선수 카드, 상세, 검색, 커뮤니티는 기존 `name_ko`/`display_name`과 검색 별칭을 그대로 사용한다. 원문 이름과 BSD ID는 유지하며, 자료의 한글명이 없는 선수는 기존 번역을 계속 표시한다.

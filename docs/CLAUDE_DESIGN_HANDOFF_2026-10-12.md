## 확정된 범위와 미확정 제안

확정: Next.js/React·Supabase·Google OAuth·Vercel, BSD 무료 데이터, 시스템 상대 선수 거래, 수요에 따른 가격 직접 변동 없음, 시즌 자산 초기화 없음, 보유 선수로 최대 11인 스쿼드. 수집·Performance·가격 발행·랭킹은 자동 처리합니다.

점수 30~80/100+, 최근 5경기 평가, 목표 가치 접근식, ±8%, 초기 5등급은 **이번 검토의 제안일 뿐 승인된 정책이 아닙니다.** UI에서 실제 점수에 10을 곱하거나 임의의 100점 척도로 변환하지 마세요. 서버 저장값과 정책 버전을 표시하세요. 새 점수/가격 규칙은 승인 후 서버·SQL·테스트와 함께 바꿉니다.

새 커뮤니티 기능도 승인된 항목부터 연결합니다. 이미지 업로드·알림·북마크·투표·공지의 동작을 가짜 성공 상태로 만들지 마세요. 디자인 제안 화면이 필요하면 운영 화면과 구분되는 목업으로 전달하세요.

## 우선 작업: 커뮤니티

현재 글/댓글/답글·본인 수정/삭제·공감·신고·본인 거래 첨부·응원 구단 권한은 연결되어 있습니다. 화면을 다시 만들면서 이를 잃지 마세요.

1. **허브의 첫 화면**: 내 응원 구단·보유 선수 라운지 바로가기, 읽을 만한 최신 글, 라운지 탐색의 순서를 잡으세요. 수십 개 구단 카드가 읽을 글을 아래로 밀지 않도록 합니다. 통합 피드가 승인되기 전에는 구단/선수 탭과 현재 API 범위를 유지할 수 있습니다.
2. **게시글 목록**: 제목·대상·분류·작성자·시간을 우선하고 공감/댓글/조회는 보조로 배치합니다. 거래 첨부는 썸네일 장식보다 선수·매입/매각·체결 당시 금액을 명확히 보여 주세요. 최신/인기·검색·분류·페이지 이동을 유지합니다.
3. **라운지**: 구단/선수 정체성, 설명, 활동 글을 한 화면에 연결합니다. 큰 장식 배너가 내용보다 우세하지 않게 합니다. 비팬·비로그인·정지 상태별 작성 안내와 가능한 다음 행동을 구분합니다.
4. **선수 라운지 탐색**: 현재 원격 검색은 첫24명만 표시합니다. 더 보기/페이지 이동은 실제 서버 쿼리와 연결해야 합니다. 프론트 데이터 24명 안에서 전체 검색하는 것으로 대체하지 마세요.
5. **글 상세/댓글**: 본문 가독성·작성자 정보·답글 깊이·삭제된 부모 안내·신고 위치를 정리합니다. 50건 단위 flat 페이지의 부모 분리 문제는 서버 개선과 함께 해결할 항목입니다. 화면에서 부모를 꾸며 넣지 않습니다.
6. **글쓰기**: 대상·분류·제목·본문·거래 첨부 순서를 명료하게 합니다. 오류 요약→해당 입력 이동, 입력 유지, 저장 중 중복 제출 방지, 편집 revision 충돌을 유지합니다. 초안 복원·이미지는 승인 후 구현합니다.
7. **변경 후 일치**: 상세 공감/댓글뿐 아니라 관련 목록의 수치·허브 게시글 수도 갱신되도록 무효화 범위를 검토합니다.
8. **관리자 커뮤니티**: 신고 내용·사유·대상·현재 상태·조치 전후를 읽기 쉽게 보여 주세요. 현재 최근200건 제한을 전체 조회로 보이게 표현하지 마세요. 전체 게시물 관리/서버 페이지네이션은 백엔드 보완 항목입니다.

사용자가 선택할 기능은 검토 문서 C01~C13에 있습니다. 구현 전 해당 ID와 실제 작업 범위를 PR에 기록하세요.

## 한글 이름 연결

이번 변경은 DB `players.name_ko`, `teams.name_ko`를 사용할 준비가 되어 있습니다. **운영 선수 3,122명 한글명은 기존 `player_names`에 저장 완료, 두 신규 컬럼과 구단 96개 값은 SQL 실행 대기**입니다. 마이그레이션 적용 뒤 선수 컬럼과 기존 `player_names`가 동기화되어 거래 견적·보유 선수·커뮤니티가 같은 이름을 보게 됩니다.

- 프론트 `Player.name`, `Team.name`을 표시용으로 사용합니다.
- `Player.originalName`, `english`, 별칭은 보존합니다. 상세에서 원어명은 보조 정보로 보여줄 수 있습니다.
- `bsd-*` ID로 관계를 연결합니다. 표시 이름으로 선수/구단을 매칭하지 않습니다.
- 현재 선수 일부는 음역 초안입니다. 언어별 관용 표기 검수가 끝난 명단이라고 표현하지 않습니다.
- DB 마이그레이션 미적용 시 선수 기존 표시명/원어명으로 동작하고 구단은 원어명으로 남을 수 있습니다. 실제 운영 반영 상태는 한글화 문서와 API에서 확인하세요.
- `lib/kickx/club-identity.ts`는 구단의 기존 영문 별칭도 사용합니다. 한글명 변경으로 구단색·엠블럼 대응이 깨지지 않도록 `english`를 유지합니다.
- 거래 내역의 이름은 체결 당시 저장값입니다. 과거 내역 이름을 현재 카탈로그로 덮어쓰지 않습니다.

## 2026-10-14 공식 대회 확대 추가 인계

경기 일정은 정규 5대 리그뿐 아니라 해당 구단이 참가한 국내 컵·유럽 대항전을 표시합니다. `Fixture`에 `stage`, `roundLabel`, `penaltiesHome`, `penaltiesAway`, `reflectionStatus`가 추가됐습니다. 승부차기 점수는 정규/연장 스코어와 분리해 표시하고, pending/withheld/partial/reflected는 기록·계산 대기/보류/일부 반영/점수 계산 완료를 뜻합니다. 과거 확정 점수는 유지될 수 있으므로 경기 종료와 가격 반영 완료를 같은 표시로 묶지 마세요. 선수·팬 구단 선택은 기존 5대 리그 범위이며 컵 상대 구단을 시장에 추가하지 않습니다. `policy.clubCompetitionsEnabled`가 true일 때 새 범위가 운영 활성화된 상태입니다. 상세 계약과 SQL 적용은 [CLUB_COMPETITIONS_2026-10-14.md](CLUB_COMPETITIONS_2026-10-14.md)를 참고하세요.

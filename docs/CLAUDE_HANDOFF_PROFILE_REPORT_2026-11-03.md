# Claude 인계: 프로필 저장·리포트 대기·사진 표시

## 프로필 아이콘

화면·서버 코드에 있던 `profiles.avatar` 컬럼이 운영 DB에 없었다. 운영 로그에서도 컬럼 부재 오류를 확인했다. 기존 `20261103160000_profile_avatar.sql`을 적용하고 PostgREST 스키마 캐시를 갱신했다. 본인 프로필만 수정하는 기존 RLS와 컬럼별 권한은 유지한다.

운영 DB에서 로그인 사용자 역할로 일반 마크와 본인이 응원하는 구단 엠블럼을 각각 저장·조회하는 검증을 수행했다. 검증 트랜잭션은 롤백했으므로 사용자의 기존 프로필은 변경하지 않았다.

일반 마크와 기본 아이콘의 화면상 이름을 제거했다. 구단 엠블럼 아래 구단명은 유지하며, 일반 마크도 화면낭독기에는 `aria-label`로 구분한다.

## 팀원 main 수정 확인

팀원의 `d5be9d2` 수정은 앞선 알림함 작업에서 합쳐졌고 개인·팀원 main 모두에 반영돼 있다. 아래 동작을 현재 코드 및 9개 UI 회귀 검사로 확인했다.

| 항목 | 반영된 동작 |
| --- | --- |
| 스쿼드 포지션 선택 | 선택한 슬롯 포지션이 기존 후보 필터보다 우선한다. FW 필터 후 DF 슬롯을 골라도 DF 후보가 보인다. |
| 스쿼드 전부 비우기 | 편집 중인 빈 라인업은 0P이며, 금융 정보 미확인 상태는 미확인으로 유지한다. |
| 관심 선수 마지막 항목 해제 | 마지막 페이지가 사라지면 유효한 이전 페이지를 조회한다. 전체가 비면 빈 목록을 표시하고 잘못된 범위를 출력하지 않는다. |
| 가격 범위 안내 | 초기 가격 범위와 전체 가격 범위를 구분하고 운영 정책의 실제 값과 서비스 시작 시점을 읽는다. |
| 검색 오류 | 긴 검색어를 클라이언트에서 검증해 잘못된 요청을 막고, 올바른 검색어로 다시 조회할 수 있다. 실제 통신 장애를 성공으로 숨기지 않는다. |
| 글자 가독성 | 보조 글자·상승/하락·포지션 색의 대비, 변동 숫자의 색상 상속, 1위 카드 보조 글자 대비를 보존했다. |

## 경기 리포트

운영 DB에 이미 완성된 리포트 11건이 있었고, 최근 실패 3건은 시작 후 약 12.07~12.17초에 실패 처리됐다. 기존 모델 요청 제한은 12초였으므로 이 제한에 걸린 정황이 있다. 해당 선수의 리포트 DB 조회는 측정 표본에서 약 53ms였다. 공급자의 원문 오류나 API 키를 DB에 기록하지 않는다.

- GET으로 저장된 점수·기여 항목·경기 전후 가치를 받는 즉시 화면에 표시한다. AI 응답 완료를 기다리며 숫자 요약까지 숨기던 흐름을 제거했다.
- AI 설명 작성 중에는 숫자 요약과 작성 상태를 함께 표시한다. 생성이 끝나면 같은 화면에 설명을 추가한다.
- 브라우저 GET은 10초, POST는 35초로 제한한다. 응답 본문이 멈춘 경우에도 제한이 적용된다. 실패하면 로딩을 끝내고 다시 확인 안내를 표시한다.
- 서버의 모델 요청 제한은 22초, DB HTTP 요청은 건당 5초, Vercel 경로의 최대 실행 시간은 45초다. 무제한 대기나 반복 재시도는 추가하지 않았다.
- 같은 계정·같은 경기의 동시 열기와 재열기는 진행 중 요청·완료 캐시를 공유한다. 다른 계정의 클라이언트 캐시는 재사용하지 않는다.
- 기존 공유 DB 캐시, 생성 잠금, 입력 해시 검증과 정책은 유지한다. 이 수정 때문에 완료 리포트를 일괄 재생성하지 않는다.
- 모델 출력의 줄바꿈·탭은 공백으로 정규화한 뒤 검증한다. 문장별 화면 줄바꿈은 그대로 유지한다.

관련 파일은 `lib/kickx/report-client.ts`, `components/kickx/match-report.tsx`, `server/kickx/report-model.ts`, `server/kickx/match-reports.ts`, `server/kickx/admin-db.ts`와 리포트 API 경로다.

## 사진: 작은 원본에 맞춰 표시

이미 사용 중인 BSD 컷아웃 옵션은 유지한다. 브라우저가 이미 받은 이미지의 실제 가로·세로를 읽으며, 크기 확인을 위한 별도 요청은 하지 않는다.

- 최대 변 길이가 200px 이하인 작은 원본에만 작은 원본용 표시를 적용한다.
- 카드·선수 상세에서 원본을 최대 150px 이내로 표시하고, 밝은 원형 배경으로 흰 테두리가 두드러지는 현상을 완화한다.
- 작은 목록 사진도 밝은 배경과 확대 없는 표시를 사용한다. 충분한 크기의 사진은 기존 컷아웃 표시를 유지한다.
- 사진 로드 실패 시 기존 실루엣 대체를 유지한다. 실제 얼굴을 AI로 재생성하지 않는다.
- 원본에 없는 세부 묘사를 복구한 것은 아니다. 고해상도 파일을 확보하면 자동으로 기존 큰 컷아웃 표시를 사용한다.

공통 로직은 `components/kickx/player-photo.ts`에 있다. 카드의 `PlayerCard`와 상세·목록의 `PlayerPortrait` 양쪽에 적용한다. `.small-source` 스타일을 손볼 때 카드와 상세를 함께 확인한다.

## 무료 플랜 사용량

사진은 기존 외부 URL을 그대로 사용하므로 새 이미지 저장·Vercel 이미지 변환·AI 이미지 API가 없다. DB에는 프로필 선택 문자열 하나를 추가했으며, 별도 사진 테이블·변환본·새 로그 테이블을 만들지 않았다.

리포트는 여전히 버튼을 눌렀을 때만 조회하고 필요한 경우 한 번 생성한다. 자동 폴링·자동 공급자 재시도는 없다. 생성 제한은 전체 하루 100회·분당 4회, 회원별 하루 10개 요청 경기, 같은 근거의 하루 재시도 제한을 유지한다. DB 캐시는 최대 3,000건·90일이며 브라우저 완료 캐시는 최대 40건·60초다. 공급자 계정의 실제 무료 할당량은 별도로 적용되며 한도 응답은 요약으로 대체한다.

검증 시점 DB 전체는 약 279MiB, 리포트 테이블은 인덱스를 포함해 96KiB이며 본문 합계는 4,740바이트였다. 이 수치는 실제 데이터·로그 축적에 따라 달라진다.

## 검증

256개 단위 검사, 프로덕션 빌드·타입 검사, 수정 파일 ESLint를 통과했다. 새 클라이언트 검사는 첫 조회·생성·본문 중단 시의 종료, 요약 선표시, 동시 요청 공유, 계정별 캐시, 재열기, 할당량 상태에서 재생성하지 않는 동작을 포함한다.

PC 1440px·모바일 390px에서 아이콘 저장 후 새로고침 유지, 일반 마크 이름 숨김·구단명 유지, 작은 원본과 큰 원본의 표시 구분, AI 응답 전에 산정 요약 표시, 생성 완료·문장 줄바꿈, 재열기 캐시, 멈춘 첫 요청의 종료를 확인했다. 화면 검사는 실제 공급자 호출 대신 별도 테스트 응답을 사용했다.

운영 DB에서는 일반 마크·구단 엠블럼의 본인 권한 저장과 리포트 조회 시간을 확인했다. 사용자 프로필을 임의로 변경하거나 AI 리포트를 대량 생성하지 않았다. 팀원 수정의 9개 UI 회귀 검사도 통과했다.

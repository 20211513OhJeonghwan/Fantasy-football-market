### 선수 상세 (점수·가격 근거)

- 가격 카드: "현재 가치 · 마지막 발행 가격", 변동률 옆 "직전 발행 대비", "가격 적용 {시각}"(기존 "최근 갱신") 문구로 정리.
- 통계 첫 칸: "최근 경기 Performance"와 "경기 1건의 저장 점수 · {rule_version}"을 표시.
- 통계 아래에 숫자 의미 범례(현재 가치 / 변동률 / Performance)를 추가. 여러 경기가 한 번에 반영되면 변동률이 한 경기 변화보다 클 수 있다고 명시.
- 최근 경기 표: 점수를 검정 바탕·노랑 글씨의 크게 보이는 칩으로 표시. 상승/하락 색은 쓰지 않으며 null은 회색 "—".
- 산정 내역에서 경기 이름을 모르면 "불러오는 중" 대신 `경기 #ID`로 표시.
- 시장·홈 표의 "변동", "Performance" 머리글에 의미 툴팁(`abbr`)을 추가하고, "오늘의 움직임"을 "최근 움직임 · 직전 발행 대비 변동폭 상위"로 변경.
- 점수에 10을 곱하거나 100점 척도로 바꾸지 않았다.

### 관리자

- **거래:** "불러온 최근 거래 / 누적 N건 중" 표기와 "최근 최대 200건" 범위 안내.
- **커뮤니티 신고**
  - 대상 유형(게시글/댓글)·현재 내용 미리보기·사유 열을 표시.
  - 검토 창에 신고 사유, "현재 내용(신고 당시 스냅샷 아님)", 조치 결과 설명(숨김/기각/복원)을 표시.
  - 최근 200건 범위를 안내.
- **처리 이력:** 행위 한글 라벨(게시물 숨김/복원/신고 기각/이용 제한/해제) + 대상 ID + 세부 정보. 최근 100건 범위 안내.

  - 불러오는 중 상태 표시, 오류 시 재시도, 공용 페이지 이동.
  - 처리 창에 현재 상태·기존 사유·가입 일시와 제한 효과 안내.

## 4. 남은 백엔드 의존성 (GPT 작업 후보)

1. **점수 내역의 경기 정보.**
   - 문제: `performance_results` 조회(`catalog-pages.ts`)에 경기 일시·상대팀·계산 시각이 없다. `player_records` 매핑에도 `fixture_id`가 없어 실제 모드에서 산정 내역 경기명을 표시할 수 없다.
   - 요청: `scoreDetails`에 `fixtureDate`, `opponent`(한글명), `minutes`, `calculatedAt`를 포함하고, 경기 일시 순으로 정렬해 주세요. D07과 연결된다.
2. **세션의 이용 제한 상태.** 세션/프로필에 `restrictedUntil`을 노출하면, 라운지·글쓰기·거래 화면이 저장 전에 제한 상태를 안내할 수 있다.
3. **C04 댓글 부모 단위 페이지.** 현재 flat 50건이다. 화면은 받은 댓글로만 트리를 만들고 부모를 꾸며 넣지 않는다.
4. **C09 갱신 범위.** 공감·댓글 후 상세는 다시 조회한다. 허브 게시글 수(`communityCounts`)는 bootstrap 응답이라, 글 생성·삭제 때만 다시 불러온다. 서버 응답에 갱신된 수치를 담아 주면 전체 bootstrap 재조회를 줄일 수 있다.
5. **C10/C12/A02/A03.**
   - 관리자 거래 200건, 신고 200건, 감사 100건 제한이 있다.
   - 신고 당시 본문 스냅샷이 없다.
   - 감사 `description`이 `action · target · JSON` 문자열이다. 구조화 필드(action, target, before, after, actor)로 내려주면 화면에서 전후 비교가 가능하다.
6. **C02 확장.** 선수 라운지 찾기는 이름순이다. 게시글 수 순·리그/구단 필터는 서버 정렬·필터가 필요하다.
7. **구단 한글명.** `teams.name_ko` SQL 실행 대기. 화면은 `Team.name`을 그대로 쓰며, 구단색 대응을 위해 `english`를 유지해야 한다.

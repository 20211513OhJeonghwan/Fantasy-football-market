# 이적·포지션 변경 선수 벤치

## 적용 정책

- 현재 선수단 데이터에서 구단 또는 GK/DF/MF/FW 포지션 변경이 확인되면 기존 보유분만 벤치로 이동한다. 과거 경기 라인업, 동일 데이터 재수집, 빈 정보 최초 보완은 변경 사건으로 취급하지 않는다.
- 변경 감지 당시 마지막 발행 가격으로 보유 평가액과 매각 가격을 동결한다. 공개 시장 시세와 새 매입에는 현재 구단·포지션·가격을 사용한다.
- 벤치는 주전 11명과 포지션 정원에서 제외한다. 같은 선수 중복 보유는 계속 금지한다. 주전 빈자리에 다른 선수를 매입할 수 있다.
- 감지 시각부터 정확히 336시간 동안 직접 매각할 수 있다. 기한이 지나면 기존 1분 알림 작업에서 자동 매각한다. 한 번에 최대 100건 처리하며 작업 경합 시 다음 실행에서 재시도한다.
- 수동·자동 매각 모두 기존 2% 수수료를 적용한다. 동결 보유분 매각에는 경기 거래 제한·현재 시세 준비 상태가 영향을 주지 않는다. 일반 선수 거래 제한은 유지한다.
- 추가 이적·포지션 변경 또는 반복 수집으로 기존 벤치 가격·기한을 연장하지 않는다. 설치 전 보유 내역을 임의로 소급 이동하지 않는다.

## 수정한 화면

- `components/kickx/squad.tsx`: 경기장 아래 변경 선수 벤치. 사유·동결 가격·자동 매각 기한·매각 버튼을 제공한다. 오른쪽 작은 시장에서도 보유 벤치 선수의 보호 가격을 표시한다.
- `components/kickx/assets.tsx`: 평가액은 동결 가격을 사용하며 동결 벤치 표시와 기한을 보인다.
- `components/kickx/ui.tsx`: 모든 매각 버튼과 모달에서 벤치 보유분을 구분한다. 동결 가격·2% 수수료·14일 기한을 안내하며, 기한 이후 수동 주문은 차단한다. 선수 상세의 거래 안내에도 보호 가격을 표시한다.
- `app/styles/squad-market.css`: 벤치 목록 2열, 640px 이하 1열. 매각 버튼과 긴 이름·기한 줄바꿈을 포함했다.
- `components/kickx/rules-report.tsx`: 사용자용 게임 규칙에 정책을 추가했다.
- 거래 내역·관리자 거래 목록: 기존 체결/벤치 매각/벤치 자동 매각을 구분한다.

## 디자인 작업 시 유지할 것

공개 시장 시세와 개인 동결 평가액을 혼동하지 않도록 가격 옆에 동결 표시를 유지한다. 벤치는 경기장의 배치 가능한 후보 명단이 아니다. 수동 배치·기간 연장·새 매입 버튼을 추가하지 않는다. 모바일에서도 사유, 동결 가격, 기한, 매각 기능이 모두 확인되어야 한다. 서버 시간과 서버 견적이 최종 기준이다.

## 데이터·비용

`holdings`에 동결 가격·시작 시각·사유 3개 nullable 필드를 추가했다. 만료 시각은 시작+336시간으로 계산한다. 거래 사유는 기존 `trades`에 nullable 필드 1개로 저장한다. 대상만 담는 작은 부분 인덱스 2개를 사용하며 새 테이블·HTTP 폴링·API 호출·Cron 작업은 추가하지 않았다.

기존 가격·경기 알림과 시세 발행 시 자산 기록에서 벤치 보유분을 제외한다. 자동 매각은 기존 거래·지갑 장부·자산 기록을 재사용한다. 주간·월간 랭킹의 과거 자산 계산도 동결 가격을 보존하며, 매각 뒤에는 이미 저장하는 체결 견적의 시각과 가격으로 확인한다.

마이그레이션: `supabase/migrations/20261108172328_roster_change_bench.sql`.

## 검증

- `npm test`: 벤치 정원 제외, 중복 보유 금지, 공개 시세와 분리된 매각, 기한 경계, 거래 사유.
- `npm run test:db`: 전체 SQL 회귀 검사와 실제 거래 흐름. 다중 보유자 변경 감지, 동결 가격, 정원 해제, 지난 견적 거부, 수동·자동 수수료 및 지갑 장부, 중복 정산 방지, 권한 분리, 동결된 과거 자산.
- `npm run lint`, `npm run build`.
- `tests/roster-bench-browser.mjs`: CI에서 320/390/1440px 벤치·자산 표시, 경기장 정원, 매각 견적과 정산, 가로 넘침 검사. 로컬 환경은 브라우저 프로세스의 소켓 생성이 제한되어 이 검사는 CI에서 실행한다.

운영 DB 적용 후 기존 지갑·보유 원가 체크섬과 거래 467건·장부 522건이 유지됨을 확인했다. 기존 작업 2개를 유지하며 새 부분 인덱스 2개의 실제 합계 크기는 16KB이다. 기존 선수들을 소급 벤치로 이동하지 않았다. 로컬 단위 테스트 290개, SQL 검사 37개, 린트·타입·프로덕션 빌드를 통과했다. 로컬 빌드는 외부 node_modules 심볼릭 링크 때문에 webpack 옵션을 사용했다.

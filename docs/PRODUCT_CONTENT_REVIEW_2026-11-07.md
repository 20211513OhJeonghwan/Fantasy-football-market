# KICK-X 콘텐츠·이용 흐름 점검

점검일: 2026-11-07 KST
기준: 이번 수정 직전 두 저장소 main의 동일한 코드 트리 `a3a94ab3ecb1995fa64ba95806b39a0052b5c94c`

## 1. 이번에 실제로 수정한 부분

스쿼드 경기장에서 보유 선수를 선택하면 나타나던 흰색 **매각** 표시를 제거했다. 이 표시는 실제 버튼이 아닌 안내용 `span`이었다. 슬롯 자체가 선택 버튼이라 그 안에 가짜 거래 버튼을 배치할 이유가 없었다.

- 선수 선택, 선택 강조, 옆 선수 시장의 실제 매각 버튼은 유지했다.
- 매입 즉시 자동 배치, 매각 즉시 슬롯 비우기, 4-3-3 정원 제한은 유지했다.
- 선수 선택 전후 슬롯 높이가 달라지지 않도록 불필요한 스타일도 제거했다.
- 가격·점수·지갑·거래 정책은 이번 작업에서 변경하지 않았다.

수정 파일: `components/kickx/squad.tsx`, `app/styles/squad-market.css`
회귀 검증: `tests/squad-market-community-browser.mjs`

## 2. 점검 범위와 확인 수준

보안, 서버 안정성, DB 용량 관리가 아니라 사용자가 보는 내용과 서비스의 이용 흐름을 중심으로 검토했다.

| 확인 방식 | 범위 | 해석 |
|---|---|---|
| 운영 화면 직접 확인 | 홈, 선수 시장, 선수 상세, 경기 일정, 구단 상세, 구단 커뮤니티, 게시글 상세, 랭킹, 이용 규칙 | 공개 화면의 실제 내용과 탐색 흐름 확인 |
| 로컬 브라우저 검증 | 26개 경로 × 1440px·390px = 52개 화면 조건, 29개 동작 확인 항목 | 일부는 빈 화면·접속 제한·없는 대상 상태이며, 전체 화면에 실데이터를 넣어 본 결과는 아님 |
| 로컬 회원 동작 검증 | 320·390·768·1024·1440px | 테스트 응답으로 매입→자동 배치→선택→실제 매각, 정원 차단, 글쓰기·첨부 취소 등을 확인 |
| 코드 검토 | 공개·회원·관리자 화면 및 관련 화면 계약 | 운영 환경에서 재현한 결함과 코드상 한계를 구분 |

운영 계정으로 거래·게시글 작성·투표를 실행하지 않았다. 실제 AI 제공자에 새 리포트를 생성시키는 운영 시험도 하지 않았다. 따라서 아래의 회원 기능 평가는 코드와 로컬 검증을 포함하며, 운영 계정의 종합 검수 완료를 뜻하지 않는다.

## 3. 현재 갖춰진 기능

이미 있는 기능을 미구현으로 오해하지 않도록 정리했다.

| 영역 | 현재 구현 |
|---|---|
| 선수 시장 | 5대 정규 리그·소속 구단, 카드 기본 표시, 두 줄 카드, 검색·포지션·구단·정렬, 관심·보유 필터, 번호·직접 입력 페이지 이동 |
| 스쿼드·거래 | 4-3-3 자동 반영, GK 1·DF 4·MF 3·FW 3, 총 11명·중복 금지, 포지션 미니 시장, 거래 모달의 정원 현황·차단 사유 |
| 선수 상세 | 1개월·3개월·전체 변동 기록, 경기 기록·대회 표시, 점수 기여 내역, 경기별 리포트, 선수 커뮤니티 진입 |
| 경기 일정 | 5대 정규 리그, 연·월 선택, 날짜 접기, 최근 일주일 기본 펼침, 리그별→시간별 표시, 구단 상세의 전체 대회 일정 |
| 커뮤니티 | 글·댓글·답글, 수정·삭제·신고·공감, 투표, 거래 첨부·취소, 작성자 활동·내 글·내 댓글 |
| 참여 자격 | 본진만 구단 글 작성, 서브팀 댓글·투표, 다른 구단 열람, 모든 선수 글 작성, 보유 인증 |
| 계정·알림 | 본진 영구 고정, 리그별 응원 구단, 변경 기간 안내, 프로필 아이콘, 가격·경기·댓글·답글 알림 및 수신 설정 |
| 랭킹·자산 | 현재 주간·월간 랭킹, 자산·평가손익·거래 내역, 작성자 활동으로 연결 |

인기 게시글, 게시글 카테고리, 별도 선수 탐색 페이지, 수동 스쿼드 배치, 다른 포메이션은 이전 결정에 따라 제거·제한된 기능이다. 이를 부족한 기능으로 다시 추가할 것을 권하지 않는다.

## 4. 콘텐츠·시스템 보완 항목

아래는 **이번에 구현한 목록이 아니라 다음 작업을 선택하기 위한 목록**이다. P1은 현재 이용 흐름 개선, P2는 서비스 확장, P3은 정책 결정이 먼저 필요한 항목이다.

### A1. 경기 결과를 한곳에서 확인하는 화면 — P1

현재 일정은 스코어와 산정 상태를 보여주지만 개별 경기 상세 경로는 없다. 결과를 보고도 그 경기에서 누가 잘했고 누구 가격이 왜 바뀌었는지 선수별 상세로 이동해서 확인해야 한다.

제안: 경기 카드를 누르면 양 팀·결과·해당 경기 선수 점수·가격 증감·리포트 입구를 함께 보여준다. 경기 후 구단 게시판이나 선수 게시판으로 이어지게 한다. 기존 점수와 변동 내역을 재사용하고 새 AI 분석을 자동 생성하지 않는다.

근거: `components/kickx/fixtures.tsx`, `app/fixtures/page.tsx`. 경기 행의 링크는 구단 상세이며 경기 상세 페이지는 없다.

### A2. 경기 결과와 가격 결과를 비교하는 요약 — P1

최근 경기 표에는 Performance가 있지만 그 경기의 증감 포인트·증감률이 같은 행에 없다. 리포트의 설명을 열기 전에는 결과와 가격을 빠르게 연결하기 어렵다.

제안: 경기 행 또는 기존 내역의 확장 부분에 `점수 / 포지션 기준 / 증감 P / 증감 % / 미출전 여부`를 간결하게 연결한다. 현재 리포트의 정형 설명을 재사용한다. 사용자가 제거한 별도 ‘선수 가치 산정 근거’ 대형 영역을 복구하자는 뜻은 아니다.

근거: `components/kickx/players.tsx`, `components/kickx/match-report.tsx`, `lib/kickx/match-report.ts`.

### A3. 내 선수 중심의 경기 탐색 — P1

경기 알림은 있지만 일정 페이지에서 ‘보유 선수 경기만’, ‘관심 선수 경기만’ 빠르게 보는 필터는 없다. 스쿼드·알림·일정이 각각 존재해도 사용자가 직접 맞춰 보게 된다.

제안: 일정에 두 가지 필터와 해당 선수 바로가기를 추가한다. 같은 구단에 여러 명을 보유해도 경기는 중복 표시하지 않는다. 관심 선수는 보유 선수와 분리하고, 수신 설정을 자동 변경하지 않는다.

### A4. 구단 상세가 명단·일정 목록에 머무름 — P1

구단 상세에는 소속 선수, 전체 대회 일정, 팬 라운지가 있다. 최근 흐름과 다음 경기를 바로 이해할 요약은 없다. 운영 화면에서 구단 일정 첫 목록은 8월 경기부터 표시됐다.

제안: 기존 일정에서 다음 경기, 최근 5경기 결과, 최근 가격 반영 경기를 요약한다. 기본 진입점은 오늘 부근으로 조정하되 과거 경기와 컵대회도 계속 조회할 수 있게 한다. 실제 리그 순위표는 별도 데이터 확보가 필요하므로 이를 현재 자료로 만들어 내지 않는다.

근거: `components/kickx/team.tsx`; 바이에른 뮌헨 운영 화면 확인.

### A5. 커뮤니티에 ‘이야기를 시작할 계기’가 부족함 — P1

글·댓글·투표·거래 첨부와 보유 인증은 이미 있다. 부족한 것은 경기 결과나 선수 판단을 게시글로 연결하는 맥락이다. 확인한 구단 게시판 첫 페이지는 10월 30일 글들이 중심이었고, 새로운 경기를 보고 바로 토론을 시작할 경로는 약했다. 이는 한 시점의 관측이며 전체 이용자 활동 통계는 아니다.

제안: 경기 결과에서 ‘이 경기 이야기’로 이동하고, 글에 실제 경기 참조 카드를 선택적으로 붙인다. 선수 글은 상세페이지의 고정 선수를 유지한다. 투표 기능은 이미 있으므로 경기 후 질문을 작성하기 편하게 연결한다. 자동으로 사람인 척하는 글을 늘리는 방향은 권하지 않는다.

### A6. 게시판을 다시 찾고 읽기 편하게 만드는 기능 — P2

내 글·내 댓글과 알림은 있으나, 읽다가 저장해 둔 글을 다시 찾는 북마크와 원치 않는 작성자 숨김 기능은 확인되지 않았다.

제안: 우선 글 저장·저장 목록을 제공한다. 작성자 숨김은 댓글·알림에 어떤 범위로 적용할지 정한 뒤 별도 구현한다. 팔로우·새 인기 영역을 한꺼번에 도입할 필요는 없다.

### A7. 커뮤니티 공지와 운영 콘텐츠 — P2

이용 규칙 페이지와 신고 처리는 있지만 게시판별 고정 안내·공지 발행과 일반 게시물 전체를 탐색하는 운영 화면은 부족하다. 관리자는 현재 최근 신고 최대 200건을 중심으로 본다.

제안: 권한·글쓰기 예절·투표 이용법을 담은 고정 안내, 전체 글·댓글 검색, 공지 고정 기능을 검토한다. 카테고리나 인기 게시글 영역을 복구할 필요는 없다.

근거: `components/kickx/admin.tsx`의 제공 범위 안내, 현재 커뮤니티 화면.

### A8. 랭킹의 기록과 신규 가입자 안내 — P1/P2

현재 주간·월간 순위는 있으나 지난 기간 조회, 내 순위 이력, 최고 기록은 없다. 집계 대상이 아닌 신규 회원에게는 내 순위가 `—`로만 보일 수 있다. ‘내 응원 구단’ 필터는 응원 구단 중 하나라도 겹치는 회원을 추리고 기존 전체 순위 번호를 유지한다.

제안: 우선 순위 없음의 사유와 다음 참여 기간, 필터의 의미를 표시한다. 이후 지난 기간·개인 기록을 제공한다. 기간 시작 후 가입자 제외라는 기존 정책이나 구단 필터의 순위 산식을 임의로 바꾸지 않는다.

근거: `components/kickx/ranking.tsx`.

### A9. 첫 이용자가 핵심 흐름을 배우기 어려움 — P1

규칙 페이지와 도움말은 있지만 실제 첫 이용 단계는 프로필 설정 후 각 화면을 직접 찾아야 한다. 특히 자동 배치, 포지션 정원, 거래 제한, 경기 후 가격 확인을 한 흐름으로 익히기 어렵다.

제안: `본진 확정 → 첫 선수 검토 → 매입 시 자동 반영 확인 → 경기 후 결과 확인`을 짧은 체크리스트로 안내한다. 매입을 강제하거나 실제 지갑으로 자동 거래하지 않는다. 자금 부족 때도 포지션별 대안과 정리할 보유 선수를 찾기 쉽게 안내한다.

### A10. 스쿼드 완성 이후의 지속 목표 — P2/P3

스쿼드는 현재 보유 선수의 자동 반영 화면이다. 11명을 채운 뒤에는 가격과 랭킹 이외의 명시적인 진행 목표가 약하다. 장기 보유 선수를 계속 지킬 이유도 가격 수익만으로는 충분하지 않을 수 있다.

제안: 우선 금전 보상 없는 개인 기록·연속 관찰·기간별 달성 배지를 검토한다. 경기력 경쟁 점수, 보유 보상, 포인트 지급은 경제 정책에 영향을 주므로 별도 승인 후 결정한다. 현재 고정 포인트 변동은 복리 팽창을 줄이지만 그 자체가 총자산 인플레를 완전히 없앤다는 보장은 아니다. 비싼 선수의 상대 수익률이 작아지는 문제도 정책상 남는 선택 사항이다.

### A11. 이적·리그 이탈·은퇴·포지션 변경 때의 사용자 안내 — P3

현재 정원과 자동 반영은 분명하지만, 선수가 범위 밖으로 이적하거나 포지션이 바뀌었을 때 기존 보유자가 어떻게 처리되는지를 사용자에게 설명하는 내용이 부족하다.

제안: 기존 보유 보호, 매각 가능 기간, 신규 매입 제한, 정원 초과 표시의 원칙을 먼저 결정한다. 사용자가 이전에 포지션 변경은 기다리자고 했으므로 이번에는 정책이나 코드를 변경하지 않았다.

상세 구현 지침은 별도 클로드 인계장의 같은 ID를 따른다.

## 6. 모바일 점검 결과

- 수정한 스쿼드 선택과 실제 매각은 320·390·768·1024·1440px에서 통과했다. 선택 때문에 슬롯 높이가 늘어나지 않는다.
- 26개 경로의 1440·390px 검증에서 문서 전체 가로 넘침은 발견되지 않았다. 화면 안의 표 스크롤이 모두 편하다는 뜻은 아니다.
- 390px에서는 경기장과 시장이 세로로 나뉘므로 U10을 우선 검토할 가치가 있다.
- 긴 한글 이름 말줄임, 표 안의 점수·리포트 접근, 긴 제목·대댓글·프로필 엠블럼 밀도는 클로드의 실데이터 시각 검수를 권한다. 자동 넘침 검사만으로 완성도를 판정하지 않았다.

검증 이미지: [390px 선택 상태](evidence/squad-selection-mobile-2026-11-07.png), [1440px 선택 상태](evidence/squad-selection-desktop-2026-11-07.png). 두 이미지는 로컬 테스트 회원·선수 데이터다.

## 7. 제외한 오진과 남겨 둔 정책

- ‘상세에서 목록으로 돌아가면 리그 필터가 초기화된다’는 의심은 실제 운영에서 재현되지 않았다. EPL 선택 후 상세 → 선수 목록 복귀 시 선택이 유지되어 오류 목록에서 제외했다. 주소로 필터를 공유하는 기능은 별도 개선 사항일 수 있으나 현재 복귀 오류로 보고하지 않는다.
- 최신 Performance가 낮아도 값이 오르는 과거 정책 문제를 이번 UI 작업에서 다시 바꾸지 않았다. 현재 산정 정책과 과거 재산정 데이터 검증은 별도 작업 범위다.
- 점수 상한 10점, 포메이션 확대, 수동 배치, 카테고리·인기 게시글 복구, 자동 보상금 지급은 이번 제안의 선행 조건이 아니다.

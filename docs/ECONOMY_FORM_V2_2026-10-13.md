2026-10-13 KST. 사용자 결정: 과거 경기로 최초 가격 환산, 가격 갱신은 최근 5출전 경기. 규칙 버전 `form-v2`.

**구현과 검증을 완료했다. 운영 DB의 신규 마이그레이션 실행 전에는 v1 정책을 계속 사용한다.** 현재 연결은 데이터 API이며 스키마 변경 SQL을 실행할 수 없으므로, 운영 전환은 아래 전체 SQL을 Supabase SQL Editor에서 한 번 실행하는 단계가 남아 있다. 이 보고서의 실측값은 운영 기록을 읽어 새 규칙을 시험 계산한 결과이지, 운영 가격을 변경한 결과가 아니다.

## 1. Performance

해당 경기 1건의 기록을 점수로 보존한다. 현재 선수 프로필 포지션이 아니라 확정 라인업의 경기 포지션을 사용한다. 100점 상한은 없으며 소수 둘째 자리까지 표시한다.

| 항목 | 배점 |
|---|---|
| 출전 | 10 + 20 × 출전분 / 90; 실제 미출전은 점수 없음 |
| 득점 | GK 50 / DF 40 / MF 35 / FW 30 |
| 도움 | 20 |
| 유효 슈팅 / 키패스 / 성공 크로스 | 3 / 2 / 1; 필드 플레이어 |
| 성공 태클 / 가로채기 | 1.5 / 2; 필드 플레이어 |
| 패스 보너스 | 30회 이상 시도·성공률 85% 이상이면 5 |
| 팀 무실점 | GK·DF 20 / MF 8, 출전분/90 비례; 퇴장 선수 제외 |
| 팀 승리 | 5 × 출전분/90 |
| 실점 | GK·DF 실제 출전 중 실점마다 -3; 퇴장/교체 이후 실점 제외 |
| GK 선방 / PK 선방 | 3 / 20 |
| 경고 / 퇴장 / 자책골 | -3 / -12 / -10 |

- 팀 무실점은 최종 스코어 기준이다. 교체 아웃 뒤 팀이 실점하면 무실점 보너스가 없지만 그 실점에 대한 감점은 없다.
- 득점과 유효 슈팅은 함께 가산한다. 두 번째 경고로 퇴장하면 앞선 경고와 퇴장만 계산한다.
- 원어 데이터·BSD 원본 JSON은 변경하지 않는다. 기본 0이 실제 0인지 알 수 없는 통계는 확정 0으로 만들지 않는다. 제공된 양수만 반영하고 제외 사유를 저장한다.
- 라인업·포지션·출전 시간·교체·득점·카드 일관성을 검사한다. 핵심 불일치, 연장전·승부차기는 보류한다. 세부 통계의 완전성을 보장할 수 없는 현재 BSD 자료는 잠정 점수로 표시한다.
- 각 기여를 소수 둘째 자리로 반올림해 화면의 항목 합계와 저장 점수를 일치시킨다.

예: 90분 무실점 수비수, 성공 태클 3회·가로채기 3회·패스 36/40은 **30+20+4.5+6+5=65.5점**. 90분 공격수, 유효 슈팅 3회·키패스 2회·팀 승리는 **48점**, 같은 기록에 1골은 **78점**, 2골은 **108점**.

## 2. 과거 기록으로 최초 가격 산정

AFL의 과거 점수→초기 가격 환산 원리를 참고하되, AFL의 실제 계수·결장 할인·드래프트 규칙을 복제하지 않았다. 아래 수치는 KICK-X의 자체 정책이다.

기준점수 50, 표본 보정 5경기, 점수 1점당 2,000P:

`초기 보정 점수 = (유효 과거 경기 점수 합계 + 50×5) / (유효 과거 출전 경기 수 + 5)`

`초기 가격 = 초기 보정 점수 × 2,000P` (1P 반올림, 10,000~1,000,000P)

| 과거 기록 | 보정 점수 | 최초 가격 |
|---|---:|---:|
| 10경기 평균 80점 | 70점 | 140,000P |
| 1경기 110점 | 60점 | 120,000P |
| 유효 기록 없음 | 50점 | 100,000P; 중립 기준, 검증된 경기력 가격이 아님 |

한 경기에서 좋은 점수를 받은 선수와 충분한 경기에서 꾸준히 좋은 선수를 같은 신뢰도로 가격화하지 않는다. 확인 불가능한 경기는 평균의 0으로 넣지 않는다. 미출전도 유효 출전 평균에서 제외한다. **이번 v2는 별도의 예측 출전 확률·선발 확률 모델을 넣지 않았다.** 실제 출전시간은 각 경기 점수에 들어가고, 작은 표본은 위 보정으로 완화한다.

### 초기 평가 기간과 이후 재계산

- SQL 적용 시점의 `pricing_reference_at`, 확보한 카탈로그의 `pricing_reference_season`을 저장해 최초 평가의 경계를 고정한다.
- 그 경계 이전 기록에서 최신 이전 시즌의 유효 기록이 있으면 사용한다. 해당 기록이 있으면 그 시즌 이후 경기를 순서대로 적용해 현재 가격을 만든다.
- 이전 시즌 자료가 없으면 경계 이전에 확보한 가장 최근 시즌의 유효 과거 기록으로 초기 가격을 산정하고 `PREVIOUS_SEASON_UNAVAILABLE`로 표시한다. 이 경우 경계 이전 경기를 초기 평가와 가격 변동에 이중 반영하지 않는다.
- 유효 자료가 없으면 중립 가격을 사용하고 `NO_USABLE_HISTORY`로 표시한다. 기록이 없다는 이유로 실제 실력을 최저 수준으로 단정하지 않는다.
- 경계 이후 새 경기는 최초 평균에 들어가지 않는다. 시즌이 바뀌어도 경계·가격·지갑을 초기화하지 않는다.
- 경계 이전 기록이 뒤늦게 수집되거나 정정되면 최초 평가도 정정될 수 있다. 이는 새 경기를 최초 평가에 계속 누적하는 것과 다르며 이전 가격 발행 revision은 보존한다.

## 3. 최근 5출전 경기 가격 변동

경기가 끝날 때마다 갱신한다. 평균을 낼 때는 최신부터 가중치 **5:4:3:2:1**을 사용한다. 과거 시즌과 현재 시즌의 출전 기록을 이어서 사용하고 미출전은 한 칸을 차지하지 않는다.

`최근 폼 F = (최신 점수×5 + 이전 점수×4 + … + 다섯 번째 점수×1) / 15`

5경기보다 적으면 부족한 칸을 선수의 초기 보정 점수로 채운다. 부족한 기록을 0점으로 넣지 않는다.

`목표 가격 T = F × 2,000P` (가격 상하한·1P 반올림)

`새 가격 = 현재 가격 + 0.4 × (T − 현재 가격)`

- 일반적인 출전은 경기당 ±8%로 제한한다. 60분 미만은 `8% × 출전분/60`으로 상한을 축소한다. 15분 출전은 최대 ±2%다.
- 가격 상하한은 10,000~1,000,000P다. 같은 경기력으로 목표가에 접근한 뒤에는 끝없이 복리 상승하지 않는다.
- 각 경기 가격을 1P 단위로 반올림한다. 음수 Performance는 가능하지만 가격은 양수다.
- 예: 최신부터 80·70·60·50·40점이면 F=66.6667, T=133,333P. 현재가 100,000P는 40% 이동 시 113,333P지만 경기 상한에 따라 **108,000P**가 된다.
- 초기 정책 전환이나 여러 경기를 묶어 발행한 변화는 직전 발행 대비 ±8%보다 클 수 있다. 경기별 변화와 직전 발행 대비 변화는 별도 근거로 보존한다.

## 4. 발행·거래·정정 처리

- TypeScript는 점수와 가격의 미리보기를 계산한다. DB는 자기 경기 일시·시즌·출전시간으로 가격을 독립 재계산한다.
- 발행 전 원본의 stats/source/fixture 수정 시각을 대조한다. 중간에 수집 자료가 바뀌면 저장하지 않고 재시도한다.
- 입력 해시와 규칙 버전을 저장한다. 스케줄러 재실행은 같은 경기에 또 상승/하락을 적용하지 않는다.
- 이미 정상 발행한 경기 기록이 불완전해지면 기존 가치·기록을 보존하고 거래를 잠시 보류한다. 새 완료 경기의 계산 보류도 최근 5경기에서 조용히 제외하고 가격을 움직이지 않는다.
- 불완전한 자료가 회복되면 동일 해시라도 대기 상태를 해제할 수 있다. 이미 체결된 거래 재요청은 대기 상태 중에도 같은 영수증을 반환한다.
- 확인된 미출전으로 정정된 기록은 불완전한 기록과 구분해 정상 재계산한다.
- 미출전·경고 문구만 변경되었을 때 가격이 같으면 가격 이력과 가격 시각을 추가하지 않는다. 유효한 거래 견적도 불필요하게 만료시키지 않는다.
- 가격이 바뀌면 보유 자산과 주간·월간 랭킹을 함께 갱신한다. 지갑 잔액·최초 지급·과거 거래 금액·보유 원가는 유지한다.
- `player_initial_values`: 초기 가격과 기간·표본·보정·사용 경기 근거.
- `player_price_results`: 경기별 변경 전후 가격·최근 폼·목표가·사용한 최대 5경기.
- `calculation_revisions.pricing`: 해당 발행 시점의 초기 가격과 경기별 가격 전체 계획. 이전 revision은 덮어쓰지 않는다.
- 새 정책 최초 계산 대기 선수는 이전 시범 가격으로 거래할 수 없다. 서버가 `PRICE_RECALCULATING`을 반환한다.

## 7. 운영 전환

1. main 배포에는 신규 엔진과 기존 v1 호환 경로가 함께 포함된다.
2. **전체 파일** `supabase/migrations/202610130001_performance_market_v2.sql`을 Supabase SQL Editor에서 한 번 실행한다. 기존 `202610090005`까지 적용되어 있어야 한다. 이름 컬럼 마이그레이션과는 독립이다.
3. 정책을 form-v2로 바꾸고 BSD 선수들을 계산 큐에 등록한다. 해당 선수 최초 산정까지 거래는 대기한다.
4. 기존 15분 예약 작업 또는 GitHub Actions `Automatic football operations`의 수동 Run workflow로 큐 처리를 시작한다. 관리자 페이지에 수동 계산 버튼을 추가하지 않았다.
5. 정책 버전·선수 계산 결과·초기 가격 근거·가격 이력·큐의 보류 사유를 확인한다. 한 번에 완료되지 않은 큐는 다음 작업에서 이어서 처리한다.

SQL 파일은 일부 예시가 아니라 스키마·독립 가격 함수·발행·거래 보호·정책 전환·큐 등록이 포함된 전체 실행 파일이다. 운영 적용 전 v1을 유지하도록 코드가 분기하므로 SQL 미실행으로 신규 규칙이 적용된 것처럼 표시하지 않는다.

# KICK-X 스쿼드·벤치 디자인 인계장

작성일: 2026년 11월 9일

## 작업 목적

포메이션 변경, 주전 배치, 벤치, 매각 안내의 시각적 완성도를 높여 주세요. 사용자가 변경 결과와 가능한 행동을 쉽게 이해하도록 정보의 순서와 간격을 정리하는 작업입니다. 기능은 구현되어 있으므로 아래 정책과 서버 연결을 유지하며 디자인을 개선해 주세요.

이 문서가 이전 스쿼드·벤치 인계장의 화면 명칭과 디자인 요청보다 우선합니다.

## 1. 이번에 반영한 내용

| 대상 | 반영 내용 |
| --- | --- |
| 스쿼드 벤치 제목·접근성 이름 | 모두 `벤치`로 통일 |
| 작은 선수 시장·내 자산의 상태 배지 | `벤치`로 통일 |
| 포메이션 변경 안내·완료 알림·게임 규칙 | `벤치로 이동`으로 통일 |
| 매각 모달·내 자산의 가격 항목 | `매각 기준가`로 통일 |
| 선수 상세의 보유 안내 | 제목은 `벤치`, 설명에 개인 보유분의 매각 기준가 표시 |
| 포메이션 선택 체크박스 | 18×18px, 최소 높이 18px, 패딩 0 적용. 일반 입력창의 최소 높이 때문에 노란 강조가 세로로 늘어나던 문제 수정 |
| 키보드 선택 표시 | 체크박스의 정사각형 포커스 테두리 유지. 마우스 클릭 때 불필요하게 큰 노란 테두리가 남지 않도록 처리 |

`동결 벤치`, `동결 선수`라는 상태 이름을 다시 사용하지 마세요. 가격이 유지되는 규칙은 설명으로 전달합니다. 내부의 `bench`, `bench.price`, 기존 DB 필드와 함수 이름은 그대로 사용합니다.

화면 문구 기준:

- 제목·상태: **벤치**
- 가격 항목: **매각 기준가**
- 이동 안내: **선택 시 벤치로 이동**
- 공통 설명: **매각 기준가는 이동 당시 가격으로 유지됩니다. 벤치 선수는 다시 배치할 수 없으며, 7일 안에 매각하지 않으면 수수료 2%를 적용해 자동 매각됩니다.**
- 남은 시간: **자동 매각까지 6일 23시간 59분**
- 만료 후 서버 처리 전: **자동 매각 처리 중**

## 2. 유지해야 하는 게임 규칙

### 포메이션과 주전 배치

- 19개 포메이션을 지원합니다. `4-6-0`, `3-6-1`, `3-3-3-1`은 제외되어 있습니다.
- GK는 1명이며 DF·MF·FW 정원은 선택한 포메이션에 따라 달라집니다.
- 새 포메이션에서 **정원을 초과하는 포지션의 선수만 사용자가 필요한 수만큼 선택해 벤치로 이동**합니다. 기존 선수 전원을 이동시키는 방식으로 바꾸지 마세요.
- 정원을 넘지 않는 선수는 주전으로 유지합니다. 정원이 같은 포메이션으로 바꿀 때는 벤치 이동 없이 경기장 줄 배치만 조정합니다.
- `선수 배치`는 주전끼리 같은 포지션의 자리로 이동·교환하는 기능입니다. 여러 MF 줄 사이의 이동도 가능합니다.
- 매입한 선수는 해당 포지션의 빈자리에 자동 반영됩니다. 매각하면 그 자리가 비워집니다.
- 경기 거래 제한 중인 선수는 포메이션 변경을 위한 벤치 이동 대상으로 선택할 수 없습니다.

### 벤치와 매각

- 이적·선수 포지션 변경이 확인되거나 포메이션 정원을 초과하면 해당 보유 선수가 벤치로 이동합니다.
- 벤치 선수는 주전 11명과 포지션별 정원에서 제외됩니다. 같은 선수를 중복 보유할 수는 없습니다.
- **벤치 선수는 주전으로 다시 배치할 수 없습니다.** 복귀 버튼이나 벤치에서 경기장으로 옮기는 드래그 동작을 추가하지 마세요.
- 이동한 개인 보유분의 평가액과 매각 기준가를 유지합니다. 공개 시장의 선수 시세와 다른 사용자의 보유분까지 멈추는 기능이 아닙니다.
- 기한은 벤치 이동 시점부터 **7일, 정확히 168시간**입니다. 기존 벤치의 시작 시각·기준가·기한을 다시 설정하지 않습니다.
- 기한 안에는 직접 매각할 수 있고, 기한 이후에는 서버가 자동 매각합니다. 수동·자동 매각 수수료는 모두 **2%**입니다.
- 벤치 보유분의 매각은 일반 선수의 경기 거래 제한·가격 산정 대기와 별도로 처리됩니다.

## 3. Claude에게 요청하는 디자인 작업

### 우선 1 — 포메이션 변경 모달

현재의 포메이션 선택 → 변경 전후 비교 → 포지션 정원 → 이동할 선수 선택 → 확정 흐름을 유지하며 정보 위계를 개선해 주세요.

- 현재와 변경 후 포메이션이 먼저 보이고, 그 아래에 초과 인원과 선택 진행 상태가 자연스럽게 이어지도록 정리합니다.
- 선택 가능한 선수, 선택한 선수, 경기 제한으로 선택할 수 없는 선수의 상태가 색상 외에도 체크·텍스트로 구분되어야 합니다.
- 같은 포지션에서 정해진 인원을 선택하면 다른 후보가 비활성화되는 동작과, 선택을 해제할 수 있는 동작을 유지합니다.
- 체크박스의 18×18px 정사각형과 키보드 포커스를 유지합니다. 조작 영역을 넓힐 때는 바깥 label의 패딩을 사용합니다.
- 긴 명단에서는 모달 본문을 스크롤하되 제목·닫기·확정 동작을 찾기 쉽게 합니다. 320px에서도 모달 밖으로 가로로 넘치지 않아야 합니다.
- 공통 규칙은 한 안내 영역에서 간결하게 보여주고 선수 행마다 긴 경고를 반복하지 않습니다.

### 우선 2 — 스쿼드의 벤치 목록

선수와 실행할 수 있는 행동이 먼저 읽히도록 카드 또는 목록을 정돈해 주세요.

| 정보 순서 | 표시할 내용 |
| --- | --- |
| 선수 식별 | 사진·이름·현재 포지션 |
| 이동 사유 | 이적 / 포지션 변경 / 포메이션 변경 |
| 가격 | 매각 기준가와 P 단위 |
| 기한 | 자동 매각까지 남은 시간과 실제 만료 일시 |
| 행동 | 매각 버튼, 만료 시 처리 중 상태 |

- 주전 경기장과 벤치 영역을 시각적으로 구분하되 벤치 전체를 오류처럼 붉게 표시하지 않습니다.
- 작은 화면에서는 1열로 정리하고 긴 이름·사유·기한 때문에 가격과 매각 버튼이 밀리거나 잘리지 않도록 합니다.
- 기간이 짧아질수록 기한을 쉽게 발견할 수 있게 하되, 기한을 프런트에서 임의로 연장하거나 바꾸지 않습니다.
- 공개 시세와 개인 매각 기준가가 다를 수 있으므로 벤치 금액 옆에는 `매각 기준가`라는 의미가 분명히 전달되어야 합니다.

### 우선 3 — 경기장·작은 시장·내 자산·매각 모달

- `선수 배치` 모드에서 선택한 선수와 이동 가능한 같은 포지션의 자리를 구분합니다. 모바일에서도 첫 선택과 두 번째 선택이 드러나야 합니다.
- DF 5명·MF 6명·5줄 포메이션에서 선수명이 겹치지 않도록 합니다. 기존 구단 유니폼과 테마를 유지합니다.
- 홈의 작은 스쿼드는 팀원이 구현한 짧은 선수명 표시를 유지합니다. 표시 이름에 공백이 있으면 마지막 이름 부분을 쓰고, 한 단어인 등록명은 그대로 표시합니다. 전체 이름의 title·접근성 이름도 유지합니다.
- 작은 선수 시장에서 벤치로 보유한 선수는 `벤치` 배지와 매각 기준가를 사용합니다. 매입 버튼으로 바꾸거나 공개 시세의 등락을 개인 벤치 가격 옆에 붙이지 않습니다.
- 내 자산·선수 상세·매각 모달에서도 같은 상태 이름과 가격 명칭을 사용합니다.
- 매각 모달의 선수·기준가·수수료·정산액·기한을 읽기 쉽게 정리하고, 저장 중·견적 만료·처리 실패 상태를 유지합니다.

### 가격 확인 중인 화면의 표현

직전 작업에서 서비스 시작일(10월 15일) 이전의 불완전한 경기 기록이 현재 가격 산정을 막던 문제를 수정했습니다. 취소된 경기는 산정 입력과 가격 변동에서 제외합니다. 사건 순서가 불명확해도 어느 순서에서나 점수가 동일하면 산정할 수 있도록 보완했습니다.

작업 시점에 거래 대상 선수의 산정 대기는 137명에서 4명으로 줄었습니다. 남은 경우는 실제 출전 시간이나 점수에 영향을 주는 사건 순서의 확인이 필요한 상태입니다. 이 숫자는 화면에 하드코딩하지 마세요.

가격 확인이 필요한 상태는 새 정책이 계속 설치 중인 것처럼 보이지 않게 `경기 기록 확인 중` 등 실제 상태에 맞춰 안내하는 방향을 권장합니다. 디자인 변경으로 경고를 숨기거나 임의의 가격·점수·산정 완료 상태를 만들어서는 안 됩니다. 재시도 버튼은 기존 견적 요청을 사용합니다.

가격·벤치 시작 시각·만료 시각·수수료·최종 잔액은 서버가 결정합니다. 화면에서는 `bench.price`, `bench.expiresAt` 등 이미 전달받는 값을 표시합니다. 남은 시간은 기존처럼 브라우저에서 30초마다 계산하며, 디자인을 위해 새로운 DB 조회·API 폴링·일별 스냅샷을 추가하지 않습니다.

## 5. 완료 전 확인

- 320 / 390 / 768 / 1440px에서 긴 이름과 기한이 잘리거나 가로 스크롤이 생기지 않는지 확인합니다.
- 키보드로 포메이션·체크박스·취소·확정·닫기를 조작할 수 있어야 합니다.
- 정원 초과가 없는 변경과 여러 포지션에서 초과가 생기는 변경을 모두 확인합니다.
- 새 벤치가 생겨도 기존 벤치의 가격·기한은 유지되어야 합니다.
- 벤치 0명·1명·여러 명, 기한 1분 미만·기한 경과·자동 매각 처리 중 상태를 확인합니다.
- 매각 완료 후 선수·포인트·빈자리 표시가 공통 회원 데이터와 맞아야 합니다.
- 사용자 화면과 접근성 이름에 이전 상태 명칭이 남아 있지 않아야 합니다.

기존 검증은 `tests/formations-browser.mjs`, `tests/roster-bench-browser.mjs`, `tests/formations.test.mjs`, `tests/database-formations.sql`, `tests/database-roster-bench.sql`에 있습니다. 브라우저 검증은 예시 회원과 가짜 API 응답을 사용하며 실제 운영 회원의 선수를 매입·매각하지 않습니다.

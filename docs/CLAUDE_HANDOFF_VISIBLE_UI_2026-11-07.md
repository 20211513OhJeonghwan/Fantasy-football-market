# 클로드 협업 인계장 — 화면 의미와 이용 흐름

작성일: 2026-11-07 KST
프로젝트: KICK-X / Next.js
대상 저장소: `hyun1290/kick-x-test`, `Patrick-KR1/Fantasy-football-market`

## 1. 요청 목적

사용자가 스쿼드의 동작하지 않는 매각 표시 제거와 전체 프로젝트의 눈에 보이는 부족함 점검을 요청했다. 코드 안정성·보안·DB 정리보다 콘텐츠를 이해하고 사용하는 경험에 집중한다.

먼저 [콘텐츠·이용 흐름 점검](PRODUCT_CONTENT_REVIEW_2026-11-07.md)을 읽어 주세요. 아래 U 항목은 UI 협업 목록이며, A 항목은 기획·기능 확장 목록입니다. **A 항목의 신규 시스템을 디자인 작업만으로 결정·구현하지 마세요.**

## 2. Codex가 이번에 수정한 내용

`components/kickx/squad.tsx`의 선택된 슬롯 안에 있던 아래 요소를 삭제했습니다.

```tsx
// 삭제한 일부 코드. 전체 컴포넌트가 아닙니다.
{onSelect && selected === i && <span className="pitch-action sell" aria-hidden="true">매각</span>}
```

- 실제 버튼이 아닌 `span`이 버튼처럼 보여 사용자 혼동을 만들었습니다.
- `app/styles/squad-market.css`의 `.pitch-action`, `.pitch-action.sell`, 관련 모바일 스타일도 제거했습니다.
- 슬롯 선택, 기존 선택 강조, 미니 시장의 실제 매각 버튼, 거래 모달은 유지했습니다.
- `tests/squad-market-community-browser.mjs`에 슬롯 안 가짜 매각 표시 없음, 선택 전후 높이 동일, 실제 매각 가능 검증을 추가했습니다.

현재 상태를 기준으로 이어서 작업해 주세요. `pitch-action`이나 슬롯 내부의 새 거래 버튼을 다시 추가하지 마세요.

## 3. 우선 협업할 화면

### U1. 경기장 선택 표현 — 기본 수정 완료

경로: `/squad`
파일: `components/kickx/squad.tsx`, `app/styles/squad-market.css`, 기존 경기장 스타일

선택한 선수의 유니폼·점선·이름 강조가 시각적으로 과할 수 있습니다. 선택 여부는 명확하게 유지하되 가짜 버튼을 추가하지 말고, 가능하면 구단 유니폼 정체성을 지나치게 덮지 않는 강조 방식을 제안해 주세요. 포커스 테두리와 `aria-pressed`는 보존합니다.

### U2. 내용이 없는 통계 영역과 선수 사진

경로: `/`, `/market`
파일: `components/kickx/home.tsx`, `players.tsx`, `player-card.tsx`, `ui.tsx`; 관련 스타일

운영 홈의 30일 추이는 확인한 모든 행에서 `—`였습니다. 경량 목록 데이터의 `history`가 비어 있으므로 색이나 선만 바꾸면 해결되지 않습니다. 카드 골·도움도 확인한 선수들에서 비어 보였습니다.

요청:

- 정보가 없으면 가짜 추이·0골로 만들지 말고 빈 칸의 비중을 줄이거나 해당 열을 조건부 생략하는 안을 우선 검토합니다.
- 데이터가 연결된 경우에만 기존 추이를 사용합니다. 3천 명의 상세 이력을 모두 내려받는 구현은 피합니다.
- 선수 사진은 원본의 흰 가장자리와 저화질을 고려해 과도한 확대를 줄이고 배경·크롭·대체 이미지 처리를 일관되게 합니다. 외부 이미지 API나 AI 보정 호출은 새로 붙이지 않습니다.
- 사진을 못 읽어도 이름·구단·포지션·가격은 식별 가능해야 합니다.

### U3. 자동 스쿼드에 맞는 표현

경로: `/`, `/portfolio`, `/squad`
파일: `home.tsx`, `assets.tsx`, `squad.tsx`

- 홈의 ‘스쿼드 편집’은 ‘스쿼드 보기’ 등 현재 자동 반영에 맞춰 정리합니다.
- 자산의 ‘출전/벤치’는 실제 경기 선발 명단이 아닙니다. `스쿼드 반영`·`정원 초과 보유`처럼 실제 상태를 설명할 표현을 검토합니다.
- 슬롯 선택은 선수 정보/거래 접근이며 수동 배치가 아님을 유지합니다.

### U4. 구단 전체 대회의 의미

경로: `/teams/[teamId]`
파일: `team.tsx`, `fixtures.tsx`

- 구단 상세는 컵·유럽대회도 보이고 가격은 5대 정규 리그 경기만 반영합니다.
- 목록 가까이에 ‘일정 열람만 / 가격 반영 대상’을 구분하는 짧은 안내나 배지를 제안합니다. 비대상 경기를 ‘산정 실패’처럼 보이게 만들지 않습니다.
- 오래된 일정부터 시작하는 현재 탐색은 오늘·다음 경기 중심으로 개선하는 안을 A4와 함께 제안합니다. 전체 대회를 필터링해 지우지 않습니다.

### U5. 선수 상세 정보의 이름과 우선순위

경로: `/players/[id]`
파일: `players.tsx`, `performance.tsx`, `match-report.tsx`

- ‘가치 분석’ 탭은 실제로 경기별 AI 리포트 입구입니다. ‘경기 리포트’ 등 내용에 맞는 이름을 제안합니다.
- 최근 경기·Performance 내역·AI 리포트의 역할을 구분하고, 같은 경기·날짜·대회 반복의 밀도를 줄입니다.
- A2의 경기별 `점수 → 실제 가격 결과` 요약은 기존 데이터 계약으로 가능한 안을 제시합니다. 새 API나 가격 산식 변경이 필요하면 백엔드 작업으로 분리합니다.
- 잠정/보류/완료/미출전은 실제 상태를 보여야 합니다. 모든 항목을 완료 배지로 칠하는 것은 해결이 아닙니다.

### U6. 음수 Performance 그래프

경로: `/players/[id]`
파일: `players.tsx`의 `PerformanceBars`

현재 절댓값으로 막대 높이를 만듭니다. 음수 점수는 0 기준선 아래, 양수는 위로 표현하는 안을 제안합니다. 음수·0·미출전·미수집을 구분하고, 20~30점 이상의 점수를 그대로 수용하세요. 10점 만점, 비율 정규화 점수로 바꾸지 않습니다.

### U7. 선수 라운지 미리보기의 정합성

경로: `/players/[id]`
파일: `players.tsx`; 필요 시 기존 커뮤니티 조회 컴포넌트

상세의 미리보기는 전체 최신 20개 글에서만 대상 선수 글을 찾습니다. 글이 있는데도 ‘첫 이야기’로 보일 수 있는 코드 경로가 있습니다. 운영의 특정 선수에서 모순을 재현한 것은 아니므로 우선 재현 후 수정합니다.

- 기존 `communityCounts`나 대상별 목록을 근거로 표시합니다.
- 모르는 상태는 ‘게시글 보기’로 처리하고 ‘첫 글’이라고 단정하지 않습니다.
- 커뮤니티 탭·사이드 미리보기·독립 라운지의 대상 선수가 일치해야 합니다.

### U8. 거래 요약의 범위

경로: `/mypage`, `/transactions`
파일: `auth.tsx`, `assets.tsx`, `lib/kickx/types.ts`

- 마이페이지의 `member.transactions.length`는 전체 거래 수가 아닐 수 있습니다. 이미 제공되는 `transactionTotal`을 우선 확인합니다.
- 거래 페이지의 `remote.data.total`은 선택한 기간·매입/매각·검색 결과 수입니다. ‘전체 기간 기준’이라는 고정 설명을 실제 필터에 맞춥니다.
- 현재 페이지 합계와 전체 조회 결과 합계는 분명히 구분합니다. 금액을 클라이언트에서 임의로 확대 계산하지 않습니다.

### U9. 권한과 빈 화면의 일치

경로: `/community/clubs`, `/community/clubs/[teamId]`, `/community/players/[playerId]`, `/ranking`

- 열람만 가능한 타 구단 게시판에서는 ‘첫 게시글 작성’을 권하지 않습니다.
- 비로그인·본진·서브팀·타 구단의 가능한 행동을 짧게 구분합니다. 실제 권한은 기존 서버 정책을 유지합니다.
- 랭킹에 없는 회원에게 가입 시점/집계 조건과 다음 참여 기간을 설명합니다. 근거 없는 예상 순위는 만들지 않습니다.
- ‘내 응원 구단’은 여러 응원 구단 중 하나라도 겹치는 회원 필터이며 전체 순위 번호가 유지됩니다. 이를 구단 내 순위로 오해하지 않게 합니다.

### U10. 작은 화면에서 선택 후 거래 이동

경로: `/squad`
390px에서는 경기장 아래에 시장이 있습니다. 선택은 되지만 실제 매각 버튼이 화면 아래라 반응이 없는 것처럼 느낄 수 있습니다.

- 선택 시 미니 시장의 선택 카드로 이동·포커스하거나 적절한 안내를 표시하는 안을 제안합니다.
- 키보드 이용 시 포커스를 예측할 수 있어야 합니다. 반복 선택마다 강제 스크롤이 튀지 않도록 합니다.
- 경기장 내부 버튼 추가로 해결하지 않습니다.
- 긴 한글 이름·GK/FW 빈자리·11명 가득 찬 상태도 검수합니다.

### U11. 작성 중 이탈

파일: `community.tsx`, `community-feed.tsx`

긴 글의 취소·앱 내부 메뉴 이동 전 경고를 일관되게 제안합니다. 현재 탭 닫기/새로고침 경고만으로 내부 이동을 모두 막지 못합니다. 작성 종료 후 다시 들어오면 거래 첨부가 남지 않는 기존 요구를 보존합니다. 원치 않는 자동 첨부 복원을 만들지 않습니다.

### U12. 공통 안내의 정확성

- 조회수는 현재 로그인한 회원의 열람을 중심으로 기록됩니다. 숫자 옆 설명을 실제 기준에 맞추는 안을 제안합니다. UI 작업으로 비회원 추적을 추가하지 않습니다.
- 미출전, 실제 0점, 미확인, 로그인 필요, 조회 대상 없음은 서로 다른 상태입니다.
- 규칙·도움말 진입점을 찾기 쉽게 하되 긴 설명을 모든 화면에 반복하지 않습니다.
- 영어 소제목·한글 제목의 기존 조합은 유지하고 페이지 하나에서 임의로 언어 체계를 바꾸지 않습니다.

## 4. 모바일 합격 기준

최소 320·390·768·1024·1440px에서 다음을 확인해 주세요.

1. 문서 전체 가로 스크롤 없음. 표의 내부 스크롤은 접근 가능하며 마지막 버튼이 잘리지 않음.
2. 스쿼드 선수 선택 전후 슬롯 높이와 경기장 배치가 바뀌지 않음. 가짜 매각 배지 없음.
3. 카드형 목록은 화면 폭에 맞춘 **두 줄**, 번호·직접 입력 페이지 이동 유지.
4. 긴 선수 이름·구단 이름·닉네임의 본진 엠블럼이 가격이나 버튼을 덮지 않음.
5. 매입 정원 초과 사유·거래 제한 해제 시점이 터치 화면에서도 읽힘.
6. 댓글·답글·투표·리포트의 버튼과 닫기 동작을 키보드와 터치로 실행 가능.
7. 음수 점수, 0점, 20~30점 이상, 미출전을 각각 넣어 확인.
8. 글쓰기에서 첨부 취소 후 재진입 시 빈 첨부, 고정 대상 선수, 필수 제목 유지.

## 5. 유지해야 할 결정

- 5대 정규 리그의 거래 범위, 구단 상세의 모든 대회 일정.
- 4-3-3 자동 배치, 최대 11명·포지션별 정원, 중복 보유 금지. 수동 배치·저장 버튼 복구 금지.
- 점수는 항목 합산이며 10점 상한이 아님. 현재 고정 포인트 가격 방식, 경기당 ±10%, 미출전 −1.5%, 가격 반영 시작 2026-10-15 KST 유지.
- 본진 영구 고정, 본진 글쓰기·서브팀 댓글/투표·타 구단 열람 권한 유지.
- 선수 글은 모든 회원 작성 가능, 선수 상세에서 대상 고정, 제목 필수, 해당 선수의 본인 거래만 첨부.
- 비로그인·서비스 시작 전 가격 결과 없는 경기의 리포트 버튼 비노출, 기존 리포트 재사용. 표시 때문에 매번 AI 호출하지 않음.
- 카테고리·인기글·구단/선수 스위치·별도 선수 탐색 페이지 복구 금지.
- 선수 사진 개선 때문에 외부 유료 서비스나 전체 원본 다운로드를 도입하지 않음.

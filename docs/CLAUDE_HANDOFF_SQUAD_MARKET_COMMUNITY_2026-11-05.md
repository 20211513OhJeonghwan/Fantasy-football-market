## 2. 확정된 동작과 이번 변경

| 가격 변동 상한 | 경기당 상승·하락 최대 10%. 목표가격 공식, 초기 가격, 경기력 점수표, 확인된 미출전 -1.5%는 그대로 유지 |
| 적용 시점 | DB 마이그레이션 실행 시점을 기록한다. 그 전에 종료된 경기는 종전 ±2%, 이후 종료되는 경기부터 ±10%. 전체 과거 가격 초기화는 하지 않음 |

| 스쿼드 매각 | 경기장 보유 선수 클릭 → 오른쪽 선택 선수 카드에서 매각 → 매각과 동시에 빈자리 반영. 소형 시장에서도 보유 선수 매각 가능 |
| 선수 시장 | 기존 매입·매각 모달을 그대로 재사용하며 동일한 정원 검사를 적용 |

| DB 거래 보호 | 견적 발급과 실제 체결에서 각각 재검사. 여러 견적·여러 창으로 정원을 넘길 수 없음. 체결·보유·지갑·자동 스쿼드를 하나의 트랜잭션에서 처리 |
| 배치 기능 | 수동 배치·이동·자리 비우기·저장·되돌리기 UI 제거. 남아 있는 호환 저장 RPC도 자동 스쿼드와 다른 배치는 거절 |
| 기존 초과 보유 | 강제 매각·자산 삭제 없음. 기존 정원 초과 계정은 초과 상태를 정리할 때까지 새 매입을 차단. 경기장에 못 들어간 보유 선수도 별도 영역에서 확인·매각 가능 |
| 구단 게시판 | 게시글 검색 왼쪽 구단 선택 드롭다운 복원. 응원하지 않는 구단도 조회 가능. 글·댓글 작성은 해당 구단 팬이라는 기존 권한 유지 |
| 선수 커뮤니티 입구 | 선수 상세 오른쪽 상단에 더 큰 커뮤니티 카드와 전체 너비 입장 버튼. 최근 Performance 패널보다 앞에 배치 |
| 선수 글쓰기 대상 | 선수 상세/라운지의 경로로 고정. 대상 선수 검색·선택 UI 제거. 대상 없는 직접 진입에는 상세페이지에서 시작하라는 안내와 시장 링크 |
| 제목 | 전체 글쓰기와 빠른 글쓰기 모두 필수 2~80자. 본문으로 제목을 자동 생성해 쓰는 서버 동작 제거. 기존 글 제목은 조회·수정 시 유지 |
| 거래 첨부 | 선수 게시판에는 본인의 해당 선수 거래만 선택 가능. API와 DB가 소유자·선수 일치를 각각 검증. 구단 글에는 기존처럼 본인 거래 첨부 가능 |
| 오래된 거래 | 최근 회원 미리보기에 없는 거래도 해당 선수로 서버 필터링해 50건씩 조회. 이전 거래는 사용자가 더 불러올 때만 요청 |
| 첨부 취소·초기화 | 명시적인 첨부 취소 버튼. 새 글쓰기 세션/대상 변경/취소 후 재진입 시 초기화. 일시적인 저장 오류에서는 본문·첨부·재시도 UUID를 유지 |
| 거래 완료 모달 | 체결 후 매입 버튼이 매각으로 바뀌어도 열린 모달의 선수·거래 방향을 고정. 자동 반영 후에도 완료 화면에서 다른 거래 견적이 새로 열리지 않음 |

±10%는 매 경기 무조건 10%가 오르내린다는 뜻이 아니다. 기존 목표가격과 직전 가격의 차이에 따라 그보다 작게 움직일 수 있다. 낮은 최근 점수에도 과거 목표가격을 따라 상승하는 기존 구조는 이번 요청에서 변경하지 않았다.

## 3. 클로드에게 부탁할 디자인 작업

### 3-1. 스쿼드 화면

- 데스크톱: 경기장 왼쪽, 소형 시장 오른쪽. 1100px 이하에서는 경기장 다음 시장 순서로 한 열 배치.
- 빈자리/보유 자리/선택한 자리와 해당 시장의 포지션 필터 연결을 더 명확하게 다듬는다.
- 비어 있는 포지션은 매입, 보유 선수는 매각이라는 동작이 자연스럽게 읽히도록 한다. 수동 배치나 후보 선수단 UI를 다시 넣지 않는다.
- 보유 정원·잔여 자리·거래 제한·가격 미산정·잔액 부족의 안내가 서로 혼동되지 않도록 시각 계층을 정리한다.
- 기존 초과 보유 자산은 별도 매각 가능한 목록이 있다. 디자인 과정에서 숨기거나 강제 매각 버튼으로 바꾸지 않는다.
- 모바일 경기장의 네 줄 선수가 잘리지 않도록 높이를 300~440px로 조절했다. 높이와 가로 비율을 함께 강제하면 최소 너비가 커져 화면 밖으로 넘칠 수 있으므로 모바일 경기장은 `aspect-ratio: auto`를 유지한다. 유니폼·선수명·선택 테두리를 320px부터 실제로 확인한다.
- 소형 시장은 8명 단위 페이지, 검색 디바운스, 기존 번호/직접 입력 페이지네이션을 사용한다. 한 번에 전체 선수 목록을 가져오지 않는다.

### 3-2. 거래 모달

- 총원 `현재 / 11`, 포지션별 `현재 / 정원`을 유지한다.
- 이번 선수의 포지션을 강조하고, 정원에 도달한 항목을 구분한다.
- 정원 초과 상태에서도 모달을 열어 이유를 읽을 수 있어야 한다. 확인 버튼만 막고, 보유 현황과 해제 방법을 설명한다.
- 모달의 견적 유효시간·거래 금액·수수료·서버 확정·중복 제출 방지를 보존한다.
- 보유 데이터가 바뀌어도 열린 모달의 거래 방향을 바꾸지 않는다. 특히 매입 완료 직후 매각 견적을 새로 요청하면 안 된다.

### 3-3. 커뮤니티

- 구단 선택 드롭다운은 게시글 검색 바로 왼쪽. 모바일에서는 위아래로 쌓아도 된다.
- 선수 커뮤니티 입장은 우측 상단에 눈에 띄게 유지한다. 구단/선수 커뮤니티 전역 스위치를 되살리지 않는다.
- 선수 대상은 고정 정보로 표시한다. 선수 검색창과 대상 선택 드롭다운을 다시 넣지 않는다.
- 제목 필수 표시는 양쪽 작성기에 똑같이 적용한다.
- 첨부 선택, 미리보기, 취소 버튼을 하나의 흐름으로 다듬는다. 선택 취소가 드롭다운 안의 빈 옵션에만 의존하면 안 된다.
- 취소와 새 작성에서는 첨부를 지우되, 서버 오류 후 재시도에는 사용자가 작성한 내용을 보존한다.

## 5. 검증과 운영 반영 순서

1. 단위 검사, 전체 마이그레이션 및 SQL 역할/권한 검사, 빌드·타입 검사, lint를 확인한다.
2. 기존 52개 경로·29개 동작 검사와 9개 UI 회귀 검사, 알림·프로필·리포트·활동 검사를 확인했다. 새 주요 동작은 5개 화면 폭에서 확인했다. 마지막 높이 보정이 모바일 너비로 전이되던 CSS 문제를 수정하고, smoke와 새 거래/글쓰기 검사를 다시 통과했다.
3. 사용자의 재개 승인 후 `apply_migration`으로 운영 DB 반영을 완료했다. 가격 상한 변경 시점은 2026-11-05 22:09:29 KST이며 그 이전에 종료된 경기는 ±2%로 재현한다.
4. migration은 기존 보유 목록을 4-3-3 표시로 채우고, 지갑·보유·거래의 무결성 지문이 바뀌면 전체 적용을 실패시킨다. 기존 자산을 팔거나 가격을 초기화하지 않는다.
5. DB가 부여한 실제 migration version `20261105130928`에 저장소 파일명을 일치시켰다. 이 SQL을 다시 실행하지 않는다.
6. 일반 회원 권한으로 매입·자동 배치·견적 재검사·중복 체결 방지·매각·자리 해제·수수료·제목 필수·선수 거래 일치·첨부 제거를 운영 DB에서 롤백 검증했다. ±10%와 과거 ±2%도 확인했다. 테스트 게시글은 0건이며 지갑·거래·보유의 무결성 값도 원래대로다.

## 6. 13번: 선수 포지션 변경 개선안 — 미구현

**권고안은 매입 당시의 스쿼드 포지션을 그 보유분에 고정하는 방식이다.**

예: MF로 매입해 MF 자리를 차지한 선수가 제공 API에서 FW로 변경되더라도, 보유 중에는 MF 슬롯과 MF 정원으로 유지한다. 매각 후 다시 매입할 때는 최신 FW 포지션과 FW 정원을 적용한다. 선수 상세에는 필요하면 `등록 포지션 MF / 현재 포지션 FW`를 구분한다. 경기력 점수는 기존처럼 해당 경기 라인업의 실제 포지션으로 계산한다.

장점은 데이터 제공사의 수정만으로 스쿼드가 깨지거나 정원을 넘거나 강제 매각이 생기지 않는 것이다. 단점은 같은 선수가 계정별로 등록 포지션이 다를 수 있다는 점이며, 복수 포지션 허용이나 변경 유예 정책을 나중에 별도로 정할 수 있다.

대안은 변경 알림과 7~14일 조정 유예를 주고 사용자가 정리하는 방식이다. 다만 유예 중 초과 정원·거래 가능 범위가 복잡해진다. 최신 API 포지션을 즉시 강제 적용하고 자동 매각하는 방식은 사용자의 자산과 스쿼드에 예기치 않은 영향을 주므로 권하지 않는다.

이번 작업에는 등록 포지션 컬럼, 유예 기간, 변경 알림, 강제 매각을 추가하지 않았다. 다음 정책 합의가 필요하다.

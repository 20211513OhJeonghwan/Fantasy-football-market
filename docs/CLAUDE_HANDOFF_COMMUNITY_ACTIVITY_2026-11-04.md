# KICK-X 커뮤니티 활동·알림·작은 화면 디자인 인계

작성일: 2026-11-04 KST.

## 1. 인계 상태

이번 요청의 기능 코드와 DB 마이그레이션, 자동 검증을 작성했다. 운영 DB에는 2026-11-04 사용자 승인 후 마이그레이션을 적용했다. 실제 DB에서 수신 설정 저장·본인 활동·알림 조회·타인 공개 아이콘·익명 접근 제한을 검증했고, 설정 검증 쓰기는 롤백했다.

배포 대상은 개인·팀 저장소 main이다. 구현 PR은 개인 #36·팀 #13이며 동일한 기능 코드와 이 인계 문서를 포함한다. 운영 DB에 이 마이그레이션을 중복 실행하지 않는다.

개인 저장소: https://github.com/hyun1290/kick-x-test

팀 저장소: https://github.com/Patrick-KR1/Fantasy-football-market

이번 인계는 2026-11-03 프로필·리포트 인계 이후의 추가 작업이다. 이전 인계 문서 `CLAUDE_HANDOFF_PROFILE_REPORT_2026-11-03.md`, `CLAUDE_HANDOFF_PLAYER_DETAIL_2026-11-03.md`도 참고한다.

## 2. 구현한 사용자 기능

### 2-1. 다른 사람의 프로필 아이콘

- 게시글과 댓글 응답에 `authorAvatar`를 전달한다.
- 게시판 작성자 칸, 글 상세, 댓글·답글에 저장된 아이콘을 표시한다.
- 랭킹은 현재 공개 랭킹에 포함된 사용자들의 아이콘만 일괄 조회한다. 전체 프로필 테이블을 공개하지 않는다.
- 본인 아이콘은 현재 세션 값을 우선해 저장 직후에도 즉시 반영한다. 타인은 서버에서 받은 공개 아이콘을 사용한다.
- 작성자 이름과 상세 아바타를 누르면 `/community/authors/[userId]`로 이동한다. 랭킹의 이름도 연결했다.
- 구단 엠블럼 외의 아이콘 이름을 화면에 다시 넣지 않는다. 접근성 이름은 유지한다.

### 2-2. 게시글 조회 기록

- 전역 프로필 객체나 게시글 객체가 갱신될 때마다 조회 기록을 보내던 코드를 제거했다.
- 사용자 ID·게시글 ID·한국 날짜를 기준으로 하루 한 번 요청한다.
- 진행 중 요청을 공유하고, 메모리와 탭별 sessionStorage에 최대 200개 성공 기록을 보관한다. 새로고침·화면 재진입에서도 중복을 줄인다.
- 실패는 성공으로 기록하지 않는다. 30초 동안 같은 실패를 반복하지 않고, 이후 재진입하면 재시도할 수 있다.
- 서버도 한국 날짜 기준 유일 키로 중복 집계를 막는다. 클라이언트 캐시는 권한이나 실제 조회 수의 근거가 아니다.

### 2-3. 댓글·답글 알림

- 기존 편지 모양 알림함에 `comment`, `reply` 유형을 추가했다. 별도 알림 테이블은 만들지 않았다.
- 새 댓글은 게시글 작성자에게, 새 답글은 부모 댓글 작성자에게 알린다. 답글 수신자와 다른 게시글 작성자에게는 댓글 알림도 전달할 수 있다.
- 자기 자신에게 알리지 않는다. 글 작성자와 부모 댓글 작성자가 같으면 답글 알림 하나만 보낸다.
- 동일 댓글 저장 요청 재시도는 알림을 다시 만들지 않는다. 댓글 수정은 새 알림을 만들지 않는다.
- 마이페이지에 `내 글의 댓글 알림`, `내 댓글의 답글 알림`을 각각 추가했다. 기본 켜짐이며 변경 즉시 서버에 저장된다. 프로필의 변경사항 저장 버튼과 별개다.
- 기존 스쿼드의 경기 알림 설정은 유지한다.
- 보관 기간은 기존과 같은 14일이다. 기존 Cron이 만료 기록을 삭제한다.
- 알림에는 본문 전체를 복제 저장하지 않는다. 조회할 때 현재 공개 댓글의 최대 160자만 제공한다.
- 삭제·숨김된 글/댓글은 알림 목록과 미확인 표시에서 제외한다. 다른 사용자의 알림함은 조회하거나 수정할 수 없다.
- 알림 클릭은 해당 글의 댓글 페이지로 이동하고 대상 댓글을 강조·스크롤한다. 50개 이후의 댓글도 찾는다.
- 기존 가격·경기 알림, 빨간 점, 모두 읽음, 이전 알림 조회는 유지한다.

### 2-4. 내 활동과 공개 작성자 활동

- 마이페이지에 `내 커뮤니티 활동` 영역을 추가했다. 내 글·내 댓글 탭과 페이지 선택을 제공한다.
- `/community/authors/[userId]`에서 공개 게시글·댓글·답글을 조회할 수 있다.
- API는 `/api/kickx/community/activity`다. 자신의 활동 조회는 검증된 로그인 사용자 기준이며, 공개 작성자 조회는 지정한 작성자의 공개 콘텐츠만 반환한다.
- 한 페이지 20개, 목록 본문 최대 160자. 전체 작성 기록을 메인 데이터에 실어 보내지 않고 영역을 열 때 필요한 페이지를 조회한다.
- 댓글 항목을 누르면 해당 댓글의 페이지와 위치로 이동한다.
- 숨김·삭제된 글이나 댓글, 숨김 글에 달린 댓글은 공개 활동에 포함하지 않는다. 이메일·지갑·비공개 거래 정보는 반환하지 않는다.
- 활동 목록, 게시글 목록, 댓글 목록은 항목 수가 줄면 서버가 유효한 마지막 페이지로 보정한다.
- 답글의 부모가 다른 페이지에 있으면 공개된 부모의 이름·짧은 문맥을 보여준다. 삭제·숨김 부모의 본문은 노출하지 않는다.

## 3. 모바일·작은 화면에서 함께 수정한 부분

- 320·390·768·1024·1440px 폭에서 새 기능과 주요 사용자 화면을 검사했다.
- 작성자 이름·긴 댓글·답글·경로 표시가 줄어든 폭에 맞게 줄바꿈되도록 했다.
- 댓글의 내용 열을 `minmax(0,1fr)`로 바꿔 긴 문자열 때문에 페이지 폭이 커지는 것을 막았다.
- 댓글 작성 푸터와 액션 버튼, 작성자 정보는 작은 화면에서 줄을 바꿔 배치한다.
- 내 활동 목록·탭·번호 선택·알림 설정을 좁은 화면에 맞게 배치했다.
- 알림함은 동적 화면 높이에 맞춰 최대 높이를 제한하고 본문 영역만 스크롤한다.
- 360px 이하에서 헤더 로고 크기를 조정해 알림함과 계정 버튼 공간을 확보했다.
- 일반 통신 오류/5xx에는 마지막 성공 데이터를 유지한다. 실제 401/403, 계정 변경, 로그아웃에는 기존 보안 초기화가 적용된다.
- 일시적 오류로 알림 Provider의 사용자 key가 바뀌거나 작성 폼이 사라지는 경로를 막았다. 마지막 정보 표시 중이라는 안내와 다시 확인 버튼을 제공한다.
- 댓글 위치로 이동한 뒤 좋아요/재조회마다 같은 위치로 다시 끌려가지 않도록 최초 이동만 수행한다.

주요 점검 화면: 홈, 선수 시장, 스쿼드, 내 자산, 거래 내역, 랭킹, 경기 일정, 선수 상세, 구단 게시판, 글 상세, 마이페이지, 작성자 활동. 실제 기기를 이용한 Safari/iOS 검수는 이번 환경에서 수행하지 않았다.

## 4. 클로드에게 요청할 디자인 보완

기능과 저장 규칙은 유지하면서 아래를 다듬어 주세요.

1. 마이페이지가 길어졌다. 내 활동·알림·프로필·자산의 시각적 위계를 정리하고, 휴대폰에서 설정 영역을 오가기 편하게 한다. 탭/접기 적용은 접근성과 상태 유지를 함께 고려한다.
2. 내 활동 목록의 제목·본문·구단/선수 표기·시간·댓글/답글 표시를 기존 KICK-X 게시판 분위기에 맞춘다. 새 카테고리 기능을 넣지는 않는다.
3. 알림함의 가격·경기·댓글·답글을 작은 아이콘/간격으로 구분하고, 읽음·미확인·빈 목록·로딩·실패·긴 닉네임을 함께 설계한다.
4. 작성자 활동 화면의 프로필 헤더·공개 활동 탭·빈 상태를 정리한다. 비공개 프로필 정보나 자산을 추가로 노출하지 않는다.
5. 320px에서는 헤더가 다소 조밀하다. 로고·알림·계정 버튼의 간격과 터치 영역, 가로로 스크롤되는 메뉴의 발견성을 다듬는다.
6. 좁은 화면의 긴 게시글·답글에서 줄 길이·행간·시간/버튼 배치를 개선한다. 부모 댓글 문맥과 현재 답글의 위계도 정리한다.
7. 키보드 탭 순서·포커스·화면낭독기 이름을 유지한다. 실제 iOS Safari/Android Chrome, 주소창 높이 변화와 화면 키보드가 열린 상태를 추가 확인한다.
8. 선수 상세의 퍼포먼스 산정 내역 시각 개선은 이전 인계 문서의 남은 디자인 과제다. 이번에는 그 영역의 레이아웃을 다시 변경하지 않았다.

## 5. DB와 배포 순서

마이그레이션 파일: `supabase/migrations/20261104011313_community_activity_and_replies.sql`.

변경 내용:
- profiles에 댓글/답글 수신 설정 2개 추가.
- 기존 user_notifications에 게시글·댓글·작성자 참조를 추가하고, 선수 없는 커뮤니티 알림도 저장할 수 있게 제약조건 확장.
- 댓글 작성 트리거와 공개 콘텐츠만 반환하는 알림 조회 도입.
- 공개 아바타·작성자 활동·댓글 위치 조회·페이지 범위 보정 RPC 추가/개선.
- 사용자/작성자별 조회와 외래 키 정리를 위한 인덱스 추가.
- 비공개 definer 함수의 schema usage와 각 함수 실행 권한을 명시. 기계 작업용 기존 함수의 접근 제한은 유지.

**운영 DB 적용과 검증을 완료했다.** 적용 전 스키마·함수·권한·제약조건은 `docs/evidence/community-schema-before-2026-11-04.json`에 보관했다. 적용 시 기존 알림은 0건이었으며, 가격·지갑·거래 기록을 초기화하거나 과거 댓글 알림을 일괄 생성하지 않았다. 새 환경에는 전체 마이그레이션을 순서대로 적용하고 운영 DB에는 중복 실행하지 않는다.

운영 마이그레이션 이력의 버전은 `20261104011313`이다. 저장소 파일명도 실제 적용 이력과 맞췄다. 기존 가격 알림 트리거와 알림 테이블 RLS는 유지되며 익명 사용자는 개인 알림 조회 함수를 실행할 수 없다.

## 6. 검증과 재현

- 단위 검사 261개 통과.
- 전체 SQL 마이그레이션과 DB 시나리오 30개 검증 통과. 새 검사에는 알림 수신자·자기 알림 제외·중복 제거·개별 수신 거부·RLS·숨김 콘텐츠 제외·공개 아이콘·댓글 위치·페이지 보정이 포함된다.
- 새 브라우저 검사: 320·390·768·1024·1440px에서 내 활동, 설정 저장 후 재조회, 타인 아이콘, 알림 이동, 조회 요청 중복 방지, 통신 오류 시 댓글 작성 내용 유지, 주요 화면의 페이지 폭 초과 여부 확인.
- 기존 알림함·스쿼드 경기 알림 검사, 프로필/리포트 검사, 기존 UI 오류 회귀 검사 9개 통과.
- 기존 전체 smoke 검사도 통과했다. 네트워크 전체 대기 대신 초기 데이터와 관련 API 완료를 기다리고, 알림·활동 API의 모의 응답을 명시해 검사 환경을 분리했다. 화면 전환과 목록 보기 변경 뒤에는 필요한 요소가 나타날 때까지 기다린다.
- CI workflow에 신규 커뮤니티 검사와 기존 알림/프로필/UI 회귀 검사도 연결했다.

실행 명령:

```sh
npm ci
npm test
npm run test:db
npm run lint
npm run build
node tests/community-activity-browser.mjs
node tests/notifications-browser.mjs
node tests/profile-report-browser.mjs
node tests/browser-ui-errors.mjs
node tests/browser-smoke.mjs
```

브라우저 검사는 CI와 동일한 Playwright 모듈/Chromium 설치가 필요하다. 기본 모듈 경로는 `/tmp/kickx-browser`이며 `KICKX_BROWSER_MODULE`로 바꿀 수 있다. 브라우저 검사에는 모의 API 응답을 사용한다. 운영 DB의 실제 알림 전달 성공을 이 결과만으로 주장하지 않는다.

캡처와 결과: `test-artifacts/community-activity/`, `test-artifacts/ui-errors/`, 알림/프로필 검사 이미지. CI artifact 보관 기간은 7일이다.

## 7. 비용과 유지할 범위

- 이 변경으로 BSD·AI·이미지 변환 API를 추가 호출하지 않는다.
- 알림은 기존 60초 요약 조회와 알림함을 열 때의 페이지 조회를 재사용한다. 새 Realtime 연결이나 별도 고빈도 폴링은 없다.
- 커뮤니티 알림은 댓글당 최대 2개이며, 식별자 중심으로 저장하고 기존 14일 정리를 사용한다.
- 내 활동은 페이지당 20개·본문 최대 160자만 조회한다.
- 가격 정책·거래 제한·4-3-3·보유 정책·5대 리그 범위·사진 원본은 변경하지 않았다.
- 카테고리·인기글·구단 선택 드롭다운·선수 탐색 페이지를 되살리지 않는다.
